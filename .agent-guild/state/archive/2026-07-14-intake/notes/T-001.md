# T-001 self-report

## What I did

Created `.agent-guild/scripts/check-provenance.py` (mode 0755, `#!/usr/bin/env
python3` shebang matching `new-task.py`). Stdlib only (argparse, re,
subprocess, tempfile, datetime). It stands alone — no import from
`.agent-guild/hooks/_lib.py` — though its `parse_frontmatter` uses the same
approach (scan for a leading `---`/`---` block, `key: value` regex per line)
scaled down since this contract has no list-valued keys.

CLI: `check-provenance.py <spec.md> [--issue N]` and `check-provenance.py
--self-test`.

Validation order (each returns the first violated rule, not all of them):
presence of `source`/`ref`/`fetched_at` -> `source` is one of
`github-issue|file|url` -> `fetched_at` matches ISO-8601 UTC (regex requires
the trailing `Z`, then `datetime.strptime` confirms it actually parses) ->
when `source: github-issue`: `issue` and `title` present, `issue` numeric,
`ref` contains `#N`, and that `N` equals `issue` -> when `--issue N` was
passed on the CLI, it equals the recorded `issue`. Every failure prints
`provenance: <rule> ...` to stderr and exits 1 (content failure); file-not-
found, no-frontmatter-at-all, and no-args are exit 3 (infra/usage), matching
the convention in `check-protected.py`.

`--self-test` writes 5 fixtures to real temp files (`tempfile.NamedTemporary
File`, cleaned up by the OS temp dir, nothing checked into the repo) and
invokes the script itself via `subprocess.run` for each one, asserting both
the exit code and — for the four failing fixtures — that the combined
stdout+stderr contains a `provenance:`-prefixed line naming the specific rule
(e.g. `"fetched_at missing"`, `"fetched_at malformed"`, `"issue missing"`,
`"--issue mismatch"`). This directly satisfies the spec's "the self-test
asserts the message, not just the exit code" requirement, since it's
literally string-matching the diagnostic.

## Judgment calls / things worth flagging

- Chose exit 1 for content-contract violations and exit 3 for infra/usage
  errors (unreadable file, missing frontmatter entirely, no CLI args) to
  match the pattern already established by `check-protected.py`. The spec
  only requires "exit nonzero" on failure, so this split is an implementation
  choice, not a spec requirement — flagging in case the checker expects a
  flatter 0/1 scheme.
- For `ref`'s `#N` extraction I used `re.search(r'#(\d+)')`, which matches
  the last `#digits` group in the string if there were more than one — the
  spec's contract only shows one `#N` per `ref`, so this shouldn't matter in
  practice.
- I noticed `.gitignore` shows as modified in `git status` (adds a `dist/`
  entry) but its mtime predates any command I ran this session, and I never
  touched it — it's not part of my artifacts and I left it alone.

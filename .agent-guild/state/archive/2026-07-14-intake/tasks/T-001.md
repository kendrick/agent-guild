## Spec excerpt

Create `.agent-guild/scripts/check-provenance.py` — a python3 stdlib-only
validator for the provenance header the `/job` intake skill writes at the top of
`.agent-guild/state/spec.md`. Make it executable and give it the same shebang
style as the neighboring scripts (see `.agent-guild/scripts/new-task.py`).

The header contract it enforces (YAML frontmatter, flat keys):

```
---
source: github-issue | file | url
ref: <owner/repo#N | path | URL>
issue: <N>                # required when source is github-issue; absent otherwise
title: <issue title>      # required when source is github-issue
fetched_at: <ISO-8601 UTC, e.g. 2026-07-14T18:00:00Z>
---
```

Usage: `check-provenance.py <spec.md> [--issue N]`. Exit 0 only when: `source`,
`ref`, `fetched_at` are present; `source` is one of the three allowed values;
`fetched_at` parses as ISO-8601 UTC; when `source: github-issue`, `issue` and
`title` are present and `issue` is consistent with the `#N` in `ref`; and with
`--issue N`, the recorded issue equals N. On failure, exit nonzero AND print a
diagnostic line naming the first violated rule (e.g.
`provenance: fetched_at missing`). A bare exit with no message is a defect.

Also implement `--self-test`: an embedded fixture battery (in-memory or temp
files; no external fixture files) that exits 0 only if all of these behave:

- a fully valid github-issue header passes;
- missing `fetched_at` fails;
- a malformed timestamp (e.g. `yesterday`) fails;
- `source: github-issue` without `issue` fails;
- `--issue N` mismatch fails;
- AND for every failing fixture, the validator emitted a diagnostic line naming
  the violated rule — the self-test asserts the message, not just the exit code.

You may parse the frontmatter with a small local parser (the repo's
`.agent-guild/hooks/_lib.py` has one you can crib the approach from, but do not
import from hooks — the script must stand alone). Write only
`.agent-guild/scripts/check-provenance.py`; touch nothing else.

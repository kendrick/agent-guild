## Spec excerpt

Create the `/job` skill at `.claude/skills/job/SKILL.md` — the guild's intake
for existing specs and GitHub issues. It turns the user's argument into
`.agent-guild/state/spec.md`, ready for `/constitution`.

Frontmatter: `name: job`, plus a `description` that makes the Skill tool select
it when the user says things like "start a job from issue 15", "kick off a job
from this spec", "build issue #12". Follow the frontmatter shape of the existing
skills (see `.claude/skills/constitution/SKILL.md`).

The skill body instructs the agent to handle the argument (`$ARGUMENTS`) forms:

1. Bare number or `#N` → `gh issue view N --json number,title,body,url` against
   the current repo.
2. `owner/repo#N` → `gh issue view N -R owner/repo --json number,title,body,url`.
3. A GitHub issue URL → `gh issue view <url> --json number,title,body,url`.
4. An existing local file path → read the file; its content becomes the spec body.
5. Any other URL → fetch it; the fetched content becomes the spec body.
6. No argument → do NOT guess. Explain the two paths: point `/job` at an issue,
   file, or URL — or skip intake and run `/constitution`, whose interview
   authors the spec.

Output: write exactly one file, `.agent-guild/state/spec.md` — the provenance
header first, then the spec content. For issues, the content is the issue title
(as a heading) plus the full issue body with its own markdown preserved: no
summarizing, no stripping, no editorializing. The header (flat YAML frontmatter):

```
---
source: github-issue | file | url
ref: <owner/repo#N | path | URL>
issue: <N>                # only when source is github-issue
title: <issue title>      # only when source is github-issue
fetched_at: <ISO-8601 UTC, e.g. 2026-07-14T18:00:00Z>
---
```

This contract is enforced by `.agent-guild/scripts/check-provenance.py`
(already built — read it and match it exactly; the skill should instruct running
`check-provenance.py .agent-guild/state/spec.md` as a final self-check, with
`--issue N` when intake came from an issue).

Failure honesty: if `gh` is missing, unauthenticated, or the issue isn't found,
report the actual error to the user and write nothing. Never fabricate spec
content. End by pointing the user at the next step: `/constitution` (which
collapses its interview when spec.md exists).

Write only `.claude/skills/job/SKILL.md`; touch nothing else.

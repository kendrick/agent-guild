## Spec excerpt

Harden `project_dir()` in `.agent-guild/hooks/_lib.py` and cover it with tests.

Current behavior: when `CLAUDE_PROJECT_DIR` is unset or invalid, the function
unconditionally returns the directory two levels up from `_lib.py`. That is
correct while the file lives at `.agent-guild/hooks/_lib.py`, but wrong the
moment the file ships inside a Claude Code plugin (two-up from the plugin's
`hooks/` is the plugin's parent, not the user's project) — state would silently
land beside the plugin.

The change:

- Keep the `CLAUDE_PROJECT_DIR` primary path exactly as is.
- In the fallback, accept the two-dirs-up candidate only if it contains a
  `.agent-guild/` directory; otherwise raise `RuntimeError` with a message that
  names the problem (fail loud, per the module's own top-of-file design rules —
  match that comment style, and explain WHY the guard exists: the plugin case).
- Do not change any other function or any hook's runtime logic.

Tests: add coverage to `.agent-guild/hooks/test_hooks.py` exercising both
fallback branches — a scratch tree WITH `.agent-guild/` is accepted, one WITHOUT
raises. The existing suite reports `49 passed, 0 failed` today; after your
change the full suite must report at least 50 passed, 0 failed. Follow the
file's existing fixture/check style.

Change only `.agent-guild/hooks/_lib.py` and `.agent-guild/hooks/test_hooks.py`;
touch nothing else. Note: the live session's hooks import this module — your
change must keep every gate working (`CLAUDE_PROJECT_DIR` is always set in real
sessions, so only the fallback branch changes behavior).

# T-004 self-report

## What I did

Created `dist/plugin/.claude-plugin/plugin.json`:

```json
{
  "name": "agent-guild",
  "description": "Runs Claude Code as an org chart: an orchestrator plans and rules, worker subagents build, and independent checker agents verify the work without trusting a self-report.",
  "version": "0.1.0",
  "author": "Kendrick Arnett",
  "hooks": "./hooks/hooks.json"
}
```

- `name`: `agent-guild`, matches `^[a-z0-9]+(-[a-z0-9]+)*$`.
- `description`: adapted from the repo README's opening line, so it matches the project's own framing rather than inventing new copy.
- `version`: `0.1.0` per the spec's example.
- `author`: `Kendrick Arnett`, taken from `git log -1 --format='%an'` since no other author metadata (no package.json, no existing manifest) exists in the repo to pull from.
- `hooks`: `./hooks/hooks.json`, per the spec's explicit instruction — this is the exact file T-003 produced at `dist/plugin/hooks/hooks.json`.
- Did not declare `agents` or `skills` — spec says auto-discovery from `dist/plugin/agents/` and `dist/plugin/skills/` (already populated by T-001/T-002) is acceptable, and declaring them wasn't required.

## Verification performed

- `python3 -c "json.load(...)"` — parses cleanly.
- Regex-checked `name` against `^[a-z0-9]+(-[a-z0-9]+)*$` — passes.
- Resolved the `hooks` path relative to the plugin root (`dist/plugin/`, not the `.claude-plugin/` subdirectory) and confirmed `dist/plugin/hooks/hooks.json` exists on disk. Note for the checker: paths in a Claude Code plugin manifest are relative to the plugin root directory, not to `.claude-plugin/` itself — resolving relative to `.claude-plugin/` (i.e., `dist/plugin/.claude-plugin/hooks/hooks.json`) would incorrectly fail even though the manifest is correct.
- Confirmed `git diff --quiet HEAD -- .claude .agent-guild/hooks .agent-guild/scripts .agent-guild/templates` is clean (C-8) — the only file touched is the new manifest under `dist/plugin/`, which is outside the protected paths and is itself a new/untracked file so it doesn't show up in a diff against HEAD anyway.

## Judgment calls / caveats

- No existing `author` field anywhere in the repo (no package.json, no prior plugin.json) to copy from; used the git author identity as the most conventional choice for a solo-maintainer OSS repo. Flagging in case the orchestrator wants a different value (e.g. an org name or GitHub handle instead of a personal name).
- `description` is a shortened paraphrase of the README's first paragraph rather than a verbatim copy, to fit typical plugin-manifest description length; full framing is preserved.

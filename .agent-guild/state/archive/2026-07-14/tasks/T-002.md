## Spec excerpt

Build the packaged hooks directory `dist/plugin/hooks/`, then make its `_lib.py`
safe to run from inside a plugin.

1. Copy all six files from `.agent-guild/hooks/` into `dist/plugin/hooks/`:
   `_lib.py`, `dispatch-guard.py`, `orchestrator-write-guard.py`, `stop-gate.py`,
   `subagent-return.py`, and `test_hooks.py`. `test_hooks.py` must travel with
   them — it locates the hooks via its own `__file__` dirname and runs them as
   subprocesses, so running `dist/plugin/hooks/test_hooks.py` genuinely exercises
   the packaged copies.

2. Harden the PACKAGED `dist/plugin/hooks/_lib.py` only (never the source under
   `.agent-guild/hooks/`). Its `project_dir()` falls back to "two directories up
   from `_lib.py`" when `CLAUDE_PROJECT_DIR` is unset. That is correct in the repo
   but wrong once `_lib.py` ships in a plugin: two-dirs-up from the plugin's
   `hooks/` resolves to the plugin's parent, not the user's project, so state
   would land beside the plugin. Inside a plugin hook `CLAUDE_PROJECT_DIR` is
   always set to the user's project, so the primary path is correct; the fallback
   must not silently misresolve. Remove it, correct it, or leave a clear comment
   flagging that it no longer locates the project from inside a plugin.

Change no hook's runtime logic — `test_hooks.py` must still report 49 passed, 0
failed against the packaged copies. Write nothing outside `dist/plugin/`.

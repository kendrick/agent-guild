## Spec excerpt

Create `scripts/build-plugin.py` (python3, stdlib only, executable) and the
checked-in manifest source `scripts/plugin-src/plugin.json`. The script builds
the publishable Claude Code plugin from the in-repo sources. Read
`docs/plugin-publish-plan.md` ("Build script" and "Verified Platform Facts")
for the design rationale before writing code.

CLI: `build-plugin.py [--out DIR] [--check]`. Default output dir is `plugin/`
at the repo root; `--out DIR` redirects (used by tests). `--help` documents all
three modes.

**The build does four things:**

1. **Copy the guild-only component set.** Agents: exactly auditor,
   checker-deterministic, checker-judgment, worker-bulk, worker-craft,
   worker-standard from `.claude/agents/` → `agents/` (byte-identical). Skills:
   the guild set from `.claude/skills/` → `skills/` (directories, full
   contents): constitution, decompose, retrospective, audition, job — plus
   `init` automatically once `.claude/skills/init/` exists (include-when-present;
   it doesn't today). NEVER ship working-memory content: no `hydrate-*`, no
   `update-working-memory`, no `hydrator.md`, no `working-memory-synchronizer.md`.
   Hooks: all six files from `.agent-guild/hooks/` → `hooks/` (byte-identical),
   plus `hooks/session-nudge.py` when it exists (it doesn't today).

2. **Generate `hooks/hooks.json` from `.claude/settings.json`** — parse the live
   registration, rewrite every command from
   `python3 "$CLAUDE_PROJECT_DIR/.agent-guild/hooks/<script>"` to
   `python3 "${CLAUDE_PLUGIN_ROOT}"/hooks/<script>`, preserve events, matchers,
   and timeouts exactly. Append a SessionStart entry ONLY when
   `session-nudge.py` shipped (include-when-present — a registration must never
   reference a file the package doesn't contain). Output shape:
   `{ "hooks": { "<Event>": [ ... ] } }`.

3. **Assemble `project-template/.agent-guild/`** — the per-project payload the
   future init skill copies into a user's repo: `CLAUDE.md` (the orchestrator
   contract from `.agent-guild/CLAUDE.md`, namespaced per #4), `scripts/` (all
   of `.agent-guild/scripts/`), `templates/` (all of `.agent-guild/templates/`).

4. **Apply the namespacing map to plugin-bound prose only.** In the packaged
   skill SKILL.md files and the packaged project-template `CLAUDE.md`, rewrite
   bare invocations `/constitution`, `/decompose`, `/retrospective`,
   `/audition`, `/job` (and `/init` when packaged) to `/agent-guild:<name>`.
   Only rewrite invocation references — never file paths like
   `.claude/skills/constitution/` or `skills/decompose/`, never directory
   names, never the repo-side source files. Keep the map explicit in one place
   in the script with a comment explaining the path-vs-prose distinction. A
   word-boundary approach that checks the character before the slash (start of
   line, whitespace, backtick, or punctuation — not a path segment) is the
   expected level of care; verify against the real contract text.

Also copy `scripts/plugin-src/plugin.json` → `.claude-plugin/plugin.json` in
the output. Author that manifest yourself: `name: agent-guild`, a short
`description`, `version: 0.1.0`, `author` as an OBJECT (`{"name": ...}` — a
plain string fails Claude Code's schema at install time), and
`"hooks": "./hooks/hooks.json"` (hooks have no auto-discovery; omit this and no
gate loads).

**`--check` mode:** rebuild into a temp dir, compare recursively against the
committed-location `plugin/` tree, and:
- exit 0 only when they match AND `claude plugin validate --strict` passes
  against the built output;
- exit nonzero, naming what differed, when any file differs or `plugin/` is
  absent;
- exit nonzero with a clear message when the `claude` CLI is missing from PATH
  (hard-fail; a skipped validation must never read as green).

The build must never modify its inputs — everything under `.claude/` and
`.agent-guild/` is read-only to it. Write only `scripts/build-plugin.py` and
`scripts/plugin-src/plugin.json`; if you generate `plugin/` while testing,
remove it before finishing.

House style: module docstring, why-comments at the non-obvious spots, small
functions, error messages that name the actual problem. References:
`.agent-guild/scripts/check-provenance.py`, `.agent-guild/scripts/new-task.py`.

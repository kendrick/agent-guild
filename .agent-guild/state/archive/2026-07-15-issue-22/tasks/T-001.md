## Spec excerpt

Create `.claude/skills/init/SKILL.md` — the skill that finishes a guild plugin
install inside a user's project. Read `docs/plugin-publish-plan.md` ("Init" and
"Verified Platform Facts") for the design rationale first. Reference skills for
voice and structure: `.claude/skills/job/SKILL.md`,
`.claude/skills/constitution/SKILL.md`.

Context you need: the plugin ships the guild's agents, skills, and hooks, but a
plugin cannot ship an always-on CLAUDE.md and `@`-imports don't expand env
vars — so the orchestrator contract and the runtime state must live in the
user's own repo. The plugin carries the per-project payload at
`${CLAUDE_PLUGIN_ROOT}/project-template/` (built by `scripts/build-plugin.py`):
`.agent-guild/CLAUDE.md` (the contract, already namespaced), `scripts/` (the
check tooling constitutions cite by path), and `templates/` (task/verdict/
dispute templates). Init copies that payload into the project and wires the
import.

Frontmatter: `name: init`, `disable-model-invocation: true` (explicit-only —
users invoke it; the model never fires it on its own), and a description that
triggers on "finish the guild install here" / "set up this project for the
guild".

The body instructs the agent through five idempotent steps, each with an
explicit exists→skip-and-report path, and a differs→ask-before-replace rule
(when asking isn't possible, skip and report; NEVER overwrite silently):

1. **The contract.** If `.agent-guild/CLAUDE.md` is missing, copy it from
   `${CLAUDE_PLUGIN_ROOT}/project-template/.agent-guild/CLAUDE.md`. If present
   and identical, report it's in place. If present but different, ask before
   replacing.
2. **The import line.** Ensure the project's root `CLAUDE.md` contains a line
   `@.agent-guild/CLAUDE.md`. Missing file → create it with that line plus a
   one-line comment noting it was added when the guild was installed. File
   exists without the line → append both lines. Line already there → report.
3. **State directories.** `mkdir -p .agent-guild/state/{tasks,verdicts,disputes,notes,log}`
   and drop a `.gitkeep` in each. Existing dirs are fine — mkdir -p semantics.
4. **Gitignore.** Append `.agent-guild/state/` to the repo's `.gitignore` when
   no line already covers it; create the file if absent.
5. **The payload.** Copy `scripts/` and `templates/` from the
   project-template into `.agent-guild/`, file by file, skipping any file that
   already exists (a user's local patches survive re-init).

Hard rules:
- Everything sources from `${CLAUDE_PLUGIN_ROOT}/project-template/`. If that
  variable arrives unsubstituted (the literal string) or the path doesn't
  exist, STOP with an error that names the situation — init is the plugin's
  install-finisher, and without an installed plugin there's no payload. Point
  the user at the plugin install (`/plugin marketplace add`, `/plugin install`).
  Never guess another payload location; never write a partial setup.
- Never touch `.claude/settings.json` — plugin users get the hooks from the
  plugin itself; merging gate registrations would double-fire every gate.
- End with a summary of what was created/skipped and the next step: run
  `/job <issue|file|url>` to intake work, or `/constitution` to author a spec
  fresh. (Write these bare — the build transform namespaces them. Where the
  skill names its own packaged identity — "you invoked /agent-guild:init" — the
  namespaced form is correct in source.)
- An explicit statement that running init twice is safe and changes nothing
  the second time.

Write only `.claude/skills/init/SKILL.md`. Touch nothing else anywhere in the
repo — the C-5 check is a repo-wide clean-footprint assertion, not a path list.

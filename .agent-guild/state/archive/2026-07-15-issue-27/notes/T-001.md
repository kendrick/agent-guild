## Judgment call worth flagging

The spec's fixture description for the "fully legal" case lists "model
override matching the tier" as one of the setup facts. I deliberately
dispatched **without** a model override instead, letting
`effective_model = override or _lib.DEFAULT_MODEL[agent]` fall through to
the `DEFAULT_MODEL` lookup. Reasoning: if an override is present, that `or`
short-circuits and `_lib.DEFAULT_MODEL[agent]` never executes — so the
KeyError-on-namespaced-DEFAULT_MODEL bug the clause explicitly calls out
("This catches a KeyError-on-namespaced-DEFAULT_MODEL bug and the
executor-mismatch trap") would go unexercised by a with-override test. The
task's `executor_model: sonnet` matches `DEFAULT_MODEL["worker-standard"]`,
so the fixture still ends up "model matching the tier" in effect, just via
the fallback path rather than an explicit override — the same one the
buggy wrapper-only alternative (raw string reaching `DEFAULT_MODEL[agent]`)
would break on.

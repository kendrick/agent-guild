## Spec excerpt

Fix the gate bypass across `.agent-guild/hooks/_lib.py` and
`.agent-guild/hooks/dispatch-guard.py`, with fixtures in
`.agent-guild/hooks/test_hooks.py`. Touch ONLY those three files — the
footprint check is a repo-wide porcelain assertion with exactly three excludes.

The bug (found live; full context in the spec): plugin-shipped agents surface
with namespaced `subagent_type` values (`agent-guild:worker-standard`,
`agent-guild:auditor`, ...), but `_lib.GUILD_AGENTS` and `DEFAULT_MODEL` key on
bare names. `dispatch-guard.py`'s first move is
`agent = ti.get("subagent_type", "")` followed by `agent not in
_lib.GUILD_AGENTS` → return 0 — so in a plugin-installed project every guild
dispatch is waved through ungated: no Task-ID requirement, no CON-audit
precondition, no tier/model matching.

The fix (seam settled by DEC-audit r0, which empirically killed the
wrapper-only alternative — dispatch-guard's `agent == "auditor"` and
`agent != executor` comparisons consume the raw string, so normalization must
happen at the source):

- Add ONE normalization helper in `_lib.py` (near the GUILD_AGENTS block):
  given a `subagent_type`, return the bare agent name by taking the suffix
  after the last `:` — `agent-guild:worker-standard` → `worker-standard`, any
  future `<ns>:` prefix behaves the same (rename-robust by construction), bare
  names pass through unchanged.
- In `dispatch-guard.py`, apply it exactly once, at the entry seam where the
  agent string is first read: keep the raw value in its own variable, e.g.
  `raw = ti.get("subagent_type", "")` then `agent = _lib.<helper>(raw)`. Every
  downstream site — `agent not in _lib.GUILD_AGENTS`, `_lib.DEFAULT_MODEL[agent]`,
  `agent == "auditor"`, `agent in _lib.CHECKER_AGENTS`, `agent != executor` —
  then works on the bare name with no further edits. Change nothing else in
  the file.
- The dispatch LOG records the RAW string (`_log(raw, ...)` — or equivalent),
  never the normalized one: the audit trail must show
  `agent-guild:worker-standard` when that is what was dispatched. Block
  messages may name either form, but prefer raw so the user sees what they
  sent.

Fixtures (test_hooks.py, existing style — drive the hook as a subprocess with
synthetic JSON against a scratch CLAUDE_PROJECT_DIR):

1. Namespaced worker dispatch without a Task-ID → exit 2, stderr contains
   "has no id line".
2. Namespaced worker dispatch, fully legal (task file at assigned, CON-audit
   PASS verdict present, model override matching the tier, bare `executor:`
   field) → exit 0. This catches a KeyError-on-namespaced-DEFAULT_MODEL bug
   and the executor-mismatch trap.
3. Bare-name regression: existing bare fixtures keep passing untouched.

Suite must end at ≥ 53 passed, 0 failed (51 today + at least two new).

House rules: stdlib only, fail-loud philosophy intact, why-comment on the
helper naming the incident class (see `in_subagent()`'s note for the voice),
fixture labels that state the behavior under test.

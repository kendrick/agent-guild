## Spec excerpt

Add an optional `job` field to the vendor-call ledger so rows from different guild runs can be told apart. Every job numbers its tasks from `T-001` and `.agent-guild/state/` is wiped between runs, so `task_id` alone is meaningless across jobs and two runs' rows currently differ only by `started_at`.

Two files change in this task.

**`.agent-guild/schemas/vendor-call.schema.json`.** Add `job` under `properties` as `{"type": "string"}` with a description saying what it holds and that an absent key means the row is unattributed. Do **not** add it to `required` — that is what keeps the 22 rows already sitting in other projects' archived ledgers valid. There is no null spelling: a row either carries a `job` string or omits the key.

**`.agent-guild/scripts/ledger-append.py`.** Add a `--job VALUE` flag and derive the value when the flag is absent. Precedence, in this order and no other:

1. `--job VALUE` when passed.
2. Otherwise, the `ref` from `.agent-guild/state/spec.md`'s provenance header, resolved against the current working directory — the same assumption `DEFAULT_LEDGER` already makes at the top of the script. Do not resolve it relative to the script's own location: the script is copied into other projects, and a script-relative path would find this repo's spec while appending to that project's ledger.
3. Otherwise, omit the key from the assembled line entirely.

The provenance header is flat YAML frontmatter at the top of `spec.md`, looking like:

```
---
source: github-issue
ref: kendrick/skills#17
issue: 17
title: "some issue title"
fetched_at: 2026-08-07T19:53:23Z
---
```

You need only `ref`. When stripping quotes from that value, strip **at most one matching pair** (`if len(val) >= 2 and val[0] == val[-1] and val[0] in "\"'"`), exactly as `.agent-guild/scripts/compose-brief.py:64` and `.agent-guild/scripts/check-provenance.py:74` already do. Do not use `str.strip("'\"")`: that removes any number of quote characters from either end regardless of balance, which is the defect filed as #127, and this is the one file we are touching specifically to avoid adding a fourth instance of it.

Update the module docstring to document the flag and the three-step precedence. Write it as a person would — the docstring is prose someone reads, and it is checked for that in a later task.

Do not write tests in this task; a separate task owns them, deliberately, so coverage and correctness are verified by different agents on different evidence. Do not regenerate the `plugin/` or `plugins/` trees; another task owns that too. Do not commit anything.

## Spec excerpt

`.agent-guild/scripts/ledger-append.py` has just gained an optional `job` field (T-001). Cover it in `.agent-guild/scripts/test_ledger_append.py` with six new cases, each labelled **verbatim** as listed. The labels are load-bearing: the check greps for them exactly, so a reworded label reads as a missing case.

- `job: derived from provenance ref` — a fixture project whose `.agent-guild/state/spec.md` carries a known `ref`, no `--job` flag passed, writes a row carrying that ref.
- `job: flag overrides provenance` — same fixture, `--job` passed, the flag wins.
- `job: absent when no spec exists` — no `spec.md`; the written row has no `job` key at all. Assert the key's absence, not that it is null.
- `job: legacy row without the key still validates` — a row dict with no `job` key passes `schema_violation()` against the amended schema. This is the issue's AC2 and the reason `job` is not in `required`.
- `job: two jobs are distinguishable` — two rows sharing `task_id: T-001` produced under different job identities are distinguishable from the row content alone, with no appeal to `started_at`.
- `job: schema keeps the field optional` — read `.agent-guild/schemas/vendor-call.schema.json` and assert `job` is under `properties`, typed `string`, and absent from `required`.

Follow the file's existing shape: it builds fixtures in temp directories and runs the script as a subprocess with that directory as cwd, rather than importing internals. Derivation reads `spec.md` relative to cwd, so a temp-dir fixture is the honest way to exercise it — and the `absent` case needs a temp dir with no `spec.md`, not this repo, which now has one.

The suite prints `  ok   {label}` for a passing case and `  FAIL {label}` for a failing one (see its `check()` helper), which is why the check can tell a passing case from a present-but-red one.

Write assertions that would actually catch a regression. A case that asserts nothing satisfies this task's own check and then fails T-001's checker, which exercises the behavior independently — the two clauses exist as a pair for exactly that reason.

A seventh `job:`-labelled case is fine if the work warrants one; the check does not count, it looks for these six.

Do not change `ledger-append.py` or the schema in this task. Do not commit anything.

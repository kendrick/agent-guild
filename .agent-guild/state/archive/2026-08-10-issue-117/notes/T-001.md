# T-001 self-report

## What I did

**`.agent-guild/schemas/vendor-call.schema.json`**: added `job` under
`properties` as `{"type": "string"}` with a description covering what it
holds and that an absent key means unattributed. Left it out of `required`.

**`.agent-guild/scripts/ledger-append.py`**:
- Added `--job VALUE` to `parse_args`.
- Added `SPEC_PATH = os.path.join(os.getcwd(), ".agent-guild", "state", "spec.md")`,
  built the same way as the existing `DEFAULT_LEDGER` (cwd-based, not
  `SCRIPT_DIR`-based) per the task's explicit warning.
- Added `derive_job(spec_path=SPEC_PATH)`: reads the leading `---`
  frontmatter block, matches a `^ref:\s*(.*)$` line, and strips at most one
  matching quote pair with the `val[0] == val[-1] and val[0] in "\"'"` form
  — the same pattern already used in `compose-brief.py:64` and
  `check-provenance.py:74`. No `str.strip("'\"")` anywhere. Returns `None`
  when the file is missing, has no frontmatter, or has no `ref:` line.
- Wired precedence into `build_line`: `args.job` if passed, else
  `derive_job()`, else the `job` key is never added to the dict at all (not
  set to `None`).
- Updated the module docstring with the three-step precedence, written as
  prose.

## Verification

Ran a manual smoke test in a scratch directory (not part of the repo,
cleaned up afterward) exercising all three precedence cases plus a quoted
`ref` value:
- fixture `spec.md` with `ref: kendrick/skills#17`, no `--job` → row carries
  `"job": "kendrick/skills#17"`.
- same fixture with `--job explicit-job#9` → row carries `"job":
  "explicit-job#9"` (flag wins).
- `spec.md` removed entirely → row has no `job` key at all (confirmed via
  `tail` on the raw JSON line, not just absence of an error).
- quoted fixture `ref: "quoted/ref#1"` → row carries `"job": "quoted/ref#1"`
  (single pair stripped correctly).

Also confirmed `git status --porcelain` shows only the two files this task
owns changed, and that `ast.parse` / `json.load` both succeed on the edited
files.

  provenance-header spec.

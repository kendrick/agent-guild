# Constitution: #100 — make the mandatory second opinion actually dispatch

Source spec: `.agent-guild/state/spec.md` (`source: file`, the plan for issue #100).

Round 2. Prior verdicts: `verdicts/CON-audit-r0.md`, `CON-audit-r1.md`, and `DEC-audit-r0.md`, which sent this document back after it had already passed.

What DEC-audit-r0 caught, auditing the decomposition and finding all three faults upstream in here. C-1's note claimed a substance check no clause performed, since the three rubrics it named all run before a single test case exists — C-9 is the repair. C-4 named a fixture nobody can build, because an exhausted lane discharges the very debt the confirmation needs standing. And C-8 asked for commit messages a checker reads before they are commits, while the commit cadence below puts four of the five commits in history before C-8's task is even dispatched — C-10 moves authorship into each task, which is the only ordering where the requirement is satisfiable.

What r0 caught, in one line each: two clauses whose checks could not fail their own most likely failing example (a predicate that ignores its `data` argument and hardcodes one lane; a `_next_move` line left untouched), and three counts of the same concept that disagreed across three documents.

One place this document deliberately outruns its spec: `spec.md`'s Tests section lists fourteen cases and C-1 requires fifteen. The fifteenth, `so: the exhausted-lane discharge follows the host lane`, is r0's finding — the spec's list has no case that can tell a correct predicate from one that hardcodes a lane. Where the two differ, C-1 governs, and the task carrying it repeats the full list so no worker has to reconcile them.

Four rules that apply to every clause, stated once:

**Every check runs from the repo root**, `/Users/k.arnett/repos/agent-guild`. The kit's scripts resolve `.agent-guild/state/` relative to cwd, and `check-diff-scope.py` compares git's relative paths against its allowlist.

**No worker commits anything.** The user asked for atomic commits along the way, and they get them — but the orchestrator makes each one, after that task's verdict of record lands and its second opinion is settled, never the worker mid-task. That is what lets C-6 read a working tree that still holds the task's own changes. A worker that committed would empty `git status --porcelain` and pass C-6 having judged nothing.

A worker does, however, **write its own commit message** (C-10), because that cadence leaves no other moment when one could be drafted and checked. Deferring every commit to the end of the job would fix the ordering and break something worse: each commit carries a `plugin/` tree regenerated from that commit's `.agent-guild/` alone, and once five tasks' changes have piled up in one working tree, the T-001-only regeneration no longer exists on disk to stage.

**This job edits the very gates that run it.** `test_hooks.py` execs the hooks under `.agent-guild/hooks/`, which is the same code the live session is running, so a half-finished edit can block the orchestrator's own turn. Workers therefore write the whole change for their task before finishing, and the orchestrator keeps `.agent-guild/state/PAUSED` in reach as the documented escape if a gate under construction locks the loop. Using PAUSED is a last resort to be reported in the retrospective, not a routine step.

**This job runs under the gate it is building, and that is deliberate.** `spec.md:110` says the work would not be run as a guild job; the user overrode that by invoking `/job`, so the spec's note records a decision that changed rather than the one in force. Two consequences follow and neither is hypothetical. First, the moment a worker lands `second_opinion_debts()` and wires it into `stop-gate.py`, this job's own verdicts of record start accruing debts — including ones written before the gate existed. The orchestrator therefore follows the dual-check regime from T-001 onward, dispatching a courier after every checker of record, so the debt ledger is already empty when the gate switches on and no task is retroactively stranded. Second, those crossings are real cross-vendor data but they judge the machinery that produces them, so the Phase 3 retrospective flags them as self-referential and leaves it to #34 whether they count. What the retrospective must not do is read the spec and this document as disagreeing about whether a guild job happened.

### C-2: The debt predicate discharges on exactly five conditions, and follows the host's lane
- **text**: `second_opinion_debts(data=None)` in `.agent-guild/hooks/_lib.py` reports a debt for a verdict-of-record stem — a file in `state/verdicts/` matching `T-NNN-<tier>-r<N>.json` with no lane suffix — unless one of these five discharges it:
  1. a sibling `…-r<N>-codex.json` exists;
  2. a sibling `…-r<N>-claude.json` exists;
  3. `state/exhausted/<lane>` exists, for the lane `courier_lane(data)` returns and no other;
  4. a waiver `…-r<N>-<lane>.denied` exists, for the same lane route 3 pins and no other;
  5. the record verdict's own `verdict` field reads `blocked`.

  A record verdict that cannot be read or parsed reports a debt, so the failure is loud rather than silent. Auditor stems (`CON-audit-*`, `DEC-audit-*`) never produce a debt, and a lane-suffixed file is never itself read as a verdict of record. The lane suffix set lives in one named constant, `COURIER_LANES`, rather than being spelled inline. The function never raises, matching the contract `paused()` and `lane_exhausted()` already hold to.
- **check**: checker-judgment: read `_lib.py` and exercise the predicate yourself in a scratch `state/verdicts/` you build by hand — do not read C-1's assertions. Construct each of the five numbered discharge conditions and confirm each one alone clears the debt; then construct a stem with none of them and confirm it owes. Then call the predicate four times against one scratch project, placing exactly one sentinel at a time and removing it before the next: with `data={"hook_host": "codex"}`, `state/exhausted/claude` discharges the debt and `state/exhausted/codex` does not; with `data={}`, the reverse. Both sentinels present at once proves nothing, since a predicate that hardcodes one lane discharges that fixture exactly as a correct one does. Separately feed it a `verdicts/` directory that does not exist, a zero-byte `.json`, and a `.json` holding `{not json`, and confirm each returns rather than raising.
- **severity**: blocker
- **failing example**: the predicate ignores `data` and hardcodes the `codex` lane. Every Claude-host check still passes, and every Codex host deadlocks in the mirror image of what C-4 prevents — `exhausted/claude` never discharges, so `stop-gate.py` demands a courier forever while `dispatch-guard.py`, which does resolve the lane correctly at `dispatch-guard.py:305-315`, refuses it on the sentinel, and the run ends at `STALLED.md`. That is the issue's third Done-when condition, both hosts producing the same artifacts, failing silently. Also failing: `blocked` treated as owing a crossing, so every failed in-family check spends a vendor call comparing against nothing; `json.load` on a truncated verdict raising out of the stop gate, turning a corrupt file into a hook crash on every turn; or a pattern loose enough that `T-001-sonnet-r0-codex.json` is itself read as a verdict of record owing its own second opinion, which makes the debt permanently unsatisfiable.

### C-3: The stop gate holds the turn open on a debt, complete tasks included
- **text**: `stop-gate.py` computes debts **before** its `if not tasks: return 0` early exit, so a task the orchestrator already moved to `complete` still blocks the turn. Its block message names both the missing lane-suffixed stem and the dispatch that settles it. `_next_move`'s `checking` line, when that task's verdict of record has landed but its lane sibling has not, says to dispatch `checker-courier` before completing, rather than the generic "act on the verdict". The livelock digest includes the debt list, so the `exhausted/<lane>` sentinel — which lives outside `verdicts/` and is invisible to `_verdicts_landed()` — registers as progress rather than as a third identical strike — `STALL_LIMIT` is 3 and the counter starts at 1, so the third identical fire is the one that stalls. The subagent no-op at the top of `main()` still runs first and is unchanged.
- **check**: checker-judgment: read `stop-gate.py` and drive it yourself as a process against scratch fixtures, asserting exit codes and stderr. Confirm all five: (1) a debt on a task whose file says `status: complete` exits 2; (2) that message names the absent stem **and** names `checker-courier` as the dispatch that settles it; (3) with an open task at `status: checking` whose verdict of record has landed and whose lane sibling has not, the block message's line for that task says to dispatch `checker-courier` before completing, and with the lane sibling present that same line reverts to the generic "act on the verdict" wording; (4) creating `exhausted/<lane>` between two otherwise identical blocked fires advances the digest instead of the strike counter; (5) a subagent-scoped payload (`agent_id` set) still exits 0 with no output and no write to `stop-gate.state`.
- **severity**: blocker
- **failing example**: debts computed after the early return, so the gate is silent on exactly the state the 2026-08-02 Claude run ended in — a completed T-001 with no crossing — and #100 ships without fixing #100. Also failing: `_next_move` left untouched, so a well-behaved orchestrator is still told to complete the task and only discovers the debt after doing it; or a message reading "1 second opinion outstanding" with no stem, leaving the orchestrator to guess which task and which retry round it owes.

### C-9: The fifteen cases assert something that would break
- **text**: Three requirements, and a case satisfies this clause only by meeting all three. **Fidelity**: each case constructs the condition its label names. A case carrying a label without building its condition — the host-lane case not driving the hook with `hook_host: codex`, not distinguishing `exhausted/claude` from `exhausted/codex` — fails whatever else it asserts. **A positive control**: where a clean exit is the whole observable, the case builds the same fixture plus one owing stem in the same project and confirms that exits 2, so it can tell "correctly ignored" from "saw nothing at all". **Non-vacuity**: the case asserts on something a plausible regression in `_lib.py`, `stop-gate.py`, or `dispatch-guard.py` would change, rather than only that the process exited or that `fresh_proj()` worked.
- **check**: checker-judgment: read the fifteen new cases in `test_hooks.py` and take the three requirements in order. First fidelity — for each case, name the condition its label claims and point at the lines that build it; a case that does not build its own condition fails here and you stop on it. Then the positive control, for every case whose sole assertion is a clean exit. Then, for each surviving case, name the assertion and one concrete mutation that would turn it red; a case you cannot name a mutation for fails. Do not treat the suite's greenness as evidence — C-1 already established it, and that comfort is what this clause exists to refuse. Mutating a scratch copy of a hook is fair game and is the strongest evidence available where a case is borderline; never edit the real tree to do it.
- **severity**: major
- **failing example**: case 6, `so: the exhausted-lane discharge follows the host lane`, written as a copy of case 5 with only the label changed — a `checking` task, a landed record verdict, `exhausted/codex` touched, the hook driven with an empty payload, asserting exit 0. It passes C-1, since the label is present and green, and it survives mutation-naming, since deleting discharge route 3 turns it red. The suite then contains no case anywhere that drives a hook with `hook_host: codex`, and the hardcoded-lane predicate CON-audit r0 spent a blocker finding on is invisible again on every Claude-host run. Also failing: `so: an auditor stem owes nothing` asserting `rc == 0` against a project whose only file is `CON-audit-r0.json`, which passes identically whether the predicate skips auditor stems or crashes on every file and returns an empty list.

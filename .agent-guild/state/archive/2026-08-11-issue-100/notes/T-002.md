## Judgment calls / things worth flagging

- **Debt matching granularity differs by gate on purpose.** In `stop-gate.py`'s `_next_move`, I matched the "dispatch courier before completing" line to the task's *current* retry round only (`stem.endswith(f"-r{retries}")`), because a task can cycle through `rework` and back to `checking` on a new round while an old round's debt is still outstanding — that old debt is already surfaced by the general debt-lines section, and conflating it with the current round's line would print the courier nudge on a round that in fact has no debt yet. In `dispatch-guard.py`, by contrast, I matched on task_id alone with no round filter, since the spec text for C-4 says "whatever its status" with no round qualifier, and a courier dispatch against *any* outstanding debt on that task should be legal. I don't think this creates any inconsistency the checker's five confirmations would catch, but it's an interpretive choice on my part where the brief didn't spell out the granularity explicitly for `dispatch-guard.py`.

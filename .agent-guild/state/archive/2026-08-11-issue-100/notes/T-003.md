## Design choices for C-9 (fidelity, positive control, non-vacuity)

- For every case whose sole assertion would otherwise be a clean exit (rc==0), I
  paired it with a positive control in the SAME scratch project: build the
  fixture, assert rc==0, then remove/flip the one thing under test and assert the
  identical fixture now blocks (rc==2). This directly answers C-9's stated trap
  (`so: an auditor stem owes nothing` asserting `rc==0` alone proves nothing) —
  case 9 builds `CON-audit-r0.json` alone (rc==0), then adds a genuinely owing
  `T-038-...json` in the SAME verdicts dir and confirms that flips to rc==2 while
  `CON-audit` never appears as an owing debt in the message.
- Case 6 (`the exhausted-lane discharge follows the host lane`) drives
  `stop-gate.py` with `{"hook_host": "codex"}` and checks `exhausted/claude`
  (must discharge) and `exhausted/codex` (must NOT) as two halves of one
  `check()` call with an AND'd condition — deliberately not two separate
  `check()` calls with the same label, since C-1's grep only needs ONE `ok` line
  to match and two separate calls would let one half silently fail without
  tripping C-1.
- Case 1 (`debt with the task at checking blocks the turn`) is the one case
  where "the condition already blocks the turn on its own" (an open task at
  `checking` blocks regardless of any debt — see the pre-existing "open task ->
  exit 2" case at line ~344). To make this case non-vacuous against that
  pre-existing coverage, I asserted the debt-specific message text ("dispatch
  checker-courier before completing") appears with the debt present, and does
  NOT appear once the verdict-of-record is removed (still blocked, but on the
  generic "act on the verdict" wording) — so the case is pinned to the debt,
  not to "checking" being open.
- Cases 13/14 (courier allowed/refused on a complete task) each also carry an
  internal positive/negative control (remove/add the debt on the identical
  fixture) even though the two cases already serve as each other's mirror,
  since C-9 asks each case to be self-contained where its main assertion is a
  clean exit.

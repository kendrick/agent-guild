## Spec excerpt

`.agent-guild/CLAUDE.md` calls the dual-check regime mandatory: once a task's checker of record returns, the orchestrator dispatches `checker-courier` for a second opinion, which lands at a lane-suffixed verdict stem. Nothing checks that it happens. On 2026-08-02 the Claude host ran a task to `complete` and never dispatched one, and no gate objected. This task builds the predicate two gates will read to close that hole. It wires nothing up — that is T-002 — so nothing in this task changes any gate's behavior.

Add two things to `.agent-guild/hooks/_lib.py`.

**A named constant.** `COURIER_LANES = ("codex", "claude")`. The same two suffixes are spelled inline at `scripts/classify-crossings.py:122`; do **not** touch that file, it is an explicit non-goal. The constant exists so the lane set has one home going forward.

**`second_opinion_debts(data=None)`.** Returns a list of outstanding second-opinion debts, one entry per owing stem, as `(task_id, stem, lane)` — `task_id` like `T-001`, `stem` the verdict-of-record stem with no lane suffix and no extension (`T-001-sonnet-r0`), `lane` the host's lane. T-002 composes the missing filename as `f"{stem}-{lane}.json"` itself. T-002's gates are written against that shape: `stop-gate.py` prints all three in its block message and `dispatch-guard.py` matches on `task_id`. Pin it, don't improvise; a worker downstream reads this file to learn the contract and there is no other place it is written down.

A **verdict of record** is a file in `.agent-guild/state/verdicts/` whose name matches `T-NNN-<tier>-r<N>.json` with no lane suffix. Each owes a debt unless discharged by any of these five conditions:

1. a sibling `…-r<N>-codex.json` exists;
2. a sibling `…-r<N>-claude.json` exists;
3. `state/exhausted/<lane>` exists, for the lane `courier_lane(data)` returns and no other;
4. a waiver `…-r<N>-<lane>.denied` exists, for the same lane route 3 pins and no other;
5. the record verdict's own `verdict` field reads `blocked`.

Route 5 is a deliberate exemption: a `blocked` verdict means the in-family check itself couldn't run, so a crossing would spend a vendor call comparing against nothing. Routes 1 and 2 cover a courier that returned anything at all — `guild-core/roles/checker-courier.md:28` turns auth failure, timeout, missing CLI, and twice-malformed vendor output all into a schema-conforming `blocked` verdict at the lane stem, so the file exists either way. Route 3 is the quota bailout, which by contract writes the sentinel and no verdict. Route 4 is the orchestrator's record that a host refused the dispatch outright, as when the Claude package shipped without `checker-courier` registered (#94) and no hook ever fired.

Four properties the checker will probe directly:

- **The lane follows the host.** Route 3 must resolve through the existing `courier_lane(data)` (`_lib.py:165`), which returns `claude` only when `data` carries `hook_host: codex`. A predicate that ignores `data` and hardcodes `codex` passes on a Claude host and deadlocks every Codex one: `exhausted/claude` never discharges, the stop gate demands a courier forever, and `dispatch-guard.py:305-315` — which does resolve the lane correctly — refuses it on the sentinel. That is the issue's third Done-when condition, both hosts producing the same artifacts, failing silently.
- **Never raises.** Same contract `paused()` (`_lib.py:145`) and `lane_exhausted()` (`_lib.py:153`) already hold to, and for the same reason: `stop-gate.py` calls this on every turn, so an exception here is a hook crash on a corrupt file. A missing `verdicts/` directory, a zero-byte `.json`, and a truncated `.json` all have to return.
- **An unreadable verdict of record blocks route 5 alone.** Routes 1 through 4 still discharge it. Unreadability means you cannot establish that the record verdict says `blocked`, so route 5 is unavailable — it does not mean the crossing never happened. Routes 1 and 2 *are* the file a courier writes, so treating an unparseable record as owing regardless would create a debt no dispatch can clear: another courier writes the same path that already exists, and the debt never discharges. That is a livelock, not a loud failure. A stem that is unreadable and has no sibling, no sentinel, and no waiver does owe, because route 5 is the only one left and it cannot be established.
- **Auditor stems and lane siblings are not verdicts of record.** `CON-audit-r0.md`, `DEC-audit-r2.json`, and `T-001-sonnet-r0-codex.json` must none of them produce a debt of their own. Match the stem pattern tightly enough that a lane sibling can't be read as a record verdict owing its own second opinion, which would make the debt permanently unsatisfiable.

Read `_lib.py`'s existing helpers before writing: `state_path()`, `courier_lane()`, `lane_exhausted()`, and `open_tasks()` establish the house style for path resolution and for never-raise error handling. Follow it rather than inventing a second one.

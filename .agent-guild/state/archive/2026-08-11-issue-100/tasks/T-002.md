## Spec excerpt

T-001 added `second_opinion_debts(data=None)` to `.agent-guild/hooks/_lib.py`. It returns the outstanding second-opinion debts: verdict-of-record stems whose `checker-courier` crossing never landed and was never explicitly denied. Nothing calls it yet. This task wires it into both gates, which is what turns the enforcement on.

**Both halves ship together, in this one task, on purpose.** They are a matched pair, and either alone is worse than neither. The stop gate demands a courier for a task the dispatch guard would refuse on status, and every run ends at `STALLED.md`.

### `stop-gate.py` — hold the turn open on a debt

Read the file first; its docstring explains what the gate is for and why the livelock backstop exists.

- Compute debts **before** the `if not tasks: return 0` early exit at line 98. This is the whole point: `open_tasks()` drops terminal tasks, so a task the orchestrator already moved to `complete` is invisible to the current gate. That is exactly the state the 2026-08-02 Claude run ended in, and the gate said nothing.
- Fold the debts into the block message. Each line names the missing lane-suffixed stem **and** says `checker-courier` is the dispatch that settles it. A message reading "1 second opinion outstanding" makes the orchestrator guess which task and which retry round it owes. Note the predicate's tuple carries `stem` as the verdict-of-record stem with no lane suffix and no extension (`T-001-sonnet-r0`), so compose the filename yourself as `f"{stem}-{lane}.json"` — printing `stem` verbatim names the file that already exists rather than the one that's missing.
- Sharpen `_next_move`'s `checking` line (line 33). Today it says "its checker is running or owes a verdict; act on the verdict". When that task's verdict of record has landed but its lane sibling has not, it should instead say to dispatch `checker-courier` before completing. With the sibling present it reverts to today's wording. This is what stops a well-behaved orchestrator from reaching `complete` prematurely in the first place; the debt list is the backstop for one that does anyway.
- Add the debt list to the livelock digest at line 103. `_verdicts_landed()` already changes when a lane verdict or a `.denied` waiver appears, but the `exhausted/<lane>` sentinel lives outside `verdicts/` and would otherwise read as a fourth identical strike — a spurious `STALLED.md` on real progress, which is the same class of bug the `_verdicts_landed()` docstring describes from the #78 run.
- Leave the subagent no-op at the top of `main()` (line 94) exactly where it is and exactly as it is. It must still run first: a subagent's Stop has no say over the orchestrator's open-task picture, and letting it touch the livelock counter is how parallel subagents trip a spurious stall.

### `dispatch-guard.py` — admit the courier so the demand can be met

The checker branch at line 280 refuses any checker dispatch on a task that isn't `checking`. Let a `checker-courier` dispatch through on a task carrying an outstanding debt whatever its status. Moving the `checker-courier` branch ahead of the generic status check is the straightforward shape.

This is defensible on the contract's own terms, and the reason belongs in a comment: the courier is explicitly not a second gate — `.agent-guild/CLAUDE.md` says the standard-stem verdict alone decides `complete` or rework — so its dispatch legality needn't track the task's gate status.

Three boundaries the checker will probe:

- **Courier-only.** `checker-deterministic` and `checker-judgment` still require `status: checking`. Dropping the status check for all checkers would let an in-family checker of record run against a task nobody re-opened.
- **Debt-gated.** A `complete` task with no debt still refuses a courier on status. The widening is an escape for a real obligation, not a blanket exemption.
- **Every other courier condition unchanged.** No model override (line 293), no `workspace-write` or `danger-full-access` (line 299), and an exhausted lane still refuses (line 307). The existing cases at `test_hooks.py:828-864` all run against a debt-free task, so **none of them exercises the path this change adds** — do not read their greenness as cover. Gate the debt so it relaxes the status requirement only: a debt-bearing `checker-courier` dispatch must still be refused for a model override, for `workspace-write` or `danger-full-access`, and for an exhausted lane. The shape to avoid is an early `if courier and has_debt: return 0` placed above those three checks, which passes every confirmation in this task's check method and quietly makes all three dead letters for every real courier dispatch — and under the new regime a courier is dispatched precisely *because* a debt exists, so "every real dispatch" is all of them.

One subtlety worth stating, because it reads like a contradiction otherwise: an exhausted lane discharges the debt outright (route 3 of the predicate), so a task cannot be both debt-bearing and lane-exhausted. The exhausted-lane refusal is therefore exercised on a task at `status: checking`, where the courier is turned away on the sentinel rather than on the status, and the existing case at `test_hooks.py:851-860` already pins it.

And `whatever its status` means what it says. A `complete` task is the case the stop gate produces most often, but a checker of record that returns FAIL puts the task at `rework` with its debt still standing, so `status in ("checking", "complete")` is wrong in a way this very job will hit. Gate on the debt, not on a status allowlist.

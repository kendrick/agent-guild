- **auditor-stem case** — a `CON-audit-r0.json` (or `DEC-audit-`) alone produces no debt. Assert on a clean exit, not on message text.
- **unreadable case** — a verdict of record holding `{not json` owes a debt rather than crashing the hook. Assert the exit code is 2, not that the process died.

No comparison data. The `codex` lane did not return inside its execution window, so the courier wrote the schema-conforming `blocked` verdict its contract calls for and finished. Nothing was substituted, no retry budget moved, and the verdict of record stands on its own.

Recorded rather than skipped, because this is the case #100 was filed about. An absence unrecorded reads later as agreement; an absence recorded is data. The `blocked` verdict at the lane stem is what discharges the debt, so the gate is satisfied by an honest failure rather than by a crossing that never happened — which is the distinction the whole job turns on.

Worth noting what was lost. C-9 asks whether seventeen test cases genuinely test what their labels claim, judged by reading them. That needs no execution and no repository access, so it is close to the ideal shape for a cross-family second opinion — the one clause in this job where the courier lane had no structural handicap. The timeout cost the evaluation its best available crossing, and #34 should count this as a lane-reliability data point rather than as a null result.

### The ledger row is wrong, and that matters more than usual here

The row this crossing appended books `duration_ms: 0` and `started_at: 2026-08-11T14:20:00Z` for two invocations that each ran to a two-minute timeout. `ledger-append.py` requires actual wall time and says null means unreported, never an invented zero. Same defect shape as the unauthorized T-002 row, which also booked `duration_ms: 0`. Not corrected here: rewriting a ledger is exactly what `ledger-append.py` exists to prevent, and a false row that stays visible is better evidence than a tidy one.

### The structural weakness this exposes in #100's own fix

A `blocked` verdict discharges a debt, and the courier writes that verdict about itself. Nothing in the gate distinguishes "the lane genuinely timed out" from "the courier never called the lane." The predicate reads a filename; `subagent-return` validates the object against a schema and confirms it names the right task and checker; neither can tell whether a vendor was contacted.

The ledger is supposed to be that independent evidence, which is why its accuracy is load-bearing rather than cosmetic. But nothing cross-checks the two: a `blocked` verdict with no ledger row at all would still discharge the debt, and a row booking `duration_ms: 0` looks the same to every gate as a row booking a real call. So the mechanism this job shipped guarantees that an absence is *recorded*, which is what the issue asked for, and does not guarantee that a recorded crossing *happened*. Those are different properties and the second one is what #34's corpus actually rests on.

The obvious tightening is to require a ledger row for the stem before a `blocked` verdict discharges anything, the way the quota path already requires ledger-before-sentinel. That is a follow-up, not a change to make while the gate is mid-flight.

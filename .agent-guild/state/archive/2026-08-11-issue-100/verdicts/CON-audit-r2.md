## C-4's five confirmations, re-derived from source

I did not take the clause's explanation of the exhausted-lane interaction on trust. Working it out from `_lib.py` and `dispatch-guard.py`:

C-2 route 3 discharges every debt in the directory the moment `state/exhausted/<lane>` exists for the lane `courier_lane(data)` returns. On a Claude host with `data={}` that lane is `codex`, so `exhausted/codex` clears the whole ledger and no task in that project is debt-bearing. The one nearby construction, `exhausted/claude` on a Claude host, leaves debts standing but leaves `lane_exhausted(courier_lane(data))` false, so the dispatch is admitted rather than refused. DEC-audit-r0's finding holds, and C-4's new confirmation (4) — a `checking` task with the host lane's sentinel set — is the correct repair. Constructible today; it is the existing case at `test_hooks.py` (`checker-courier dispatch under exhausted/codex → exit 2`).

The other four:

1. Courier on a `complete` task with a debt exits 0. The widening's whole point; constructible from a landed record verdict with no sibling.
2. Courier on a `complete` task with no debt exits 2 naming the status. Construct "no debt" with a `-codex.json` sibling or a `blocked` record; the courier branch's debt gate is then false, control falls to the generic status check at `dispatch-guard.py:281`, and its message names the status verbatim.
3. `checker-judgment` on that same debt-bearing `complete` task exits 2 naming the status. Same branch, unwidened.
5. Courier on a debt-bearing task at `status: rework` exits 0. Constructible, and it closes the `status in ("checking", "complete")` mutation DEC-audit-r0 flagged as most likely to survive.

One thing the clause understates. Confirmation (4) is not only constructible, it is the only confirmation that catches the naive implementation of C-4's own instruction. "Move the `checker-courier` branch ahead of the generic status check" invites hoisting the *entire* sub-branch — override, sandbox, and lane checks included — and gating all of it on the debt. Under that shape a no-debt courier dispatch skips the lane check entirely and exits 0 on the status check alone, which breaks confirmation (4) and the existing exhausted-lane suite case together. Only the status test may be debt-conditional; the courier's own three conditions must stay unconditional. C-4's text does say "Every other courier condition is unchanged," so the requirement is present — noting the mechanism because it is why confirmation (4) earns its place beyond satisfying DEC-audit-r0.

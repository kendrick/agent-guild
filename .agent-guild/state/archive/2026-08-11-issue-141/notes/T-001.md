# T-001 rework (sonnet r1) — self-report

## What was wrong

The r0 checker found a real gap: C-8 requires the allow-cases to cover each
of C-5's four discharge behaviors, and the fourth — a `.denied` waiver still
discharging at a stem that carries an unauthorized lane verdict — had no
case pinning it. The only existing waiver test (test_hooks.py case 7,
T-036) exercised a bare stem with no lane sibling present at all, so it
couldn't distinguish "waiver discharges" from "waiver discharges only when
nothing else is on disk at that stem."

The checker proved the gap was real by producing an alternate ordering of
`second_opinion_debts()` that branches on "is a lane file present at all"
before ever asking about authorization — closing the waiver route off for
any stem with an unauthorized sibling — and showing the shipped suite (178
cases) didn't notice.

## What I changed

Added exactly one new case, 7b, immediately after case 7 in
`.agent-guild/hooks/test_hooks.py` (T-048): a hand-written, unauthorized
codex-lane sibling (`T-048-sonnet-r0-codex.json`, no reservation behind it —
same shape as case 3's forged fixture) sits at the stem alongside a
`.denied` waiver. Confirms `stop-gate.py` exits 0 (discharged) with both
files present, then exits 2 (owing) once the waiver is removed but the
unauthorized sibling stays. No production code changed — `_lib.py`,
`dispatch-guard.py`, and `subagent-return.py` are untouched from the
already-passing r0 commit (5f3705e); this rework only extended the test
suite named in the diagnosis.

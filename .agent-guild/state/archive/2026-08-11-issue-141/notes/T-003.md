Before writing, I re-derived the checker's account from the code rather than trusting it. `reserve_crossing` (`_lib.py:252`) returns early without writing a record when `{stem}-{lane}.json` already exists, and `promote_crossing` (`_lib.py:286`) opens whatever `.authorized` record is at the path and promotes it if `record["task_id"] == tid`. I confirmed that with a probe against a scratch project (`scratchpad/probe.py`), driving `_lib` directly:

- Courier died after a legal dispatch: reserve `True`, debt owed, re-dispatch reserve `False` but promote `True`, `crossing_authorized` `True`, debts `[]`. The debt clears without a waiver.
- Forged file with no reservation ever: re-dispatch reserve `False`, promote `False`, debt still owed. Only the `.denied` waiver clears it.

That is the split the prose now carries.

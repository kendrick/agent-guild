## Spec excerpt

A lane-suffixed verdict currently discharges a second-opinion debt by existing.
`_lib.second_opinion_debts()` looks for `T-NNN-<tier>-r<N>-<lane>.json` in
`state/verdicts/` and nothing ties that file to a dispatch that authorized it, so
any agent with a write can discharge any task's debt and #100's debt gate
believes it. This is not hypothetical: during the #100 run a courier dispatched
for T-001 wrote a verdict, a rendered sibling, and a ledger row for **T-002**,
and the artifacts are preserved under
`.agent-guild/state/archive/2026-08-11-issue-100/quarantine/`.

Build the authorization record. The seam is fixed and is the only one available:
`dispatch-guard.py` has `tid`, `task['executor_model']`, `retries`, and
`_lib.courier_lane(data)`, so it can compute a crossing's exact stem and record
what it finds at dispatch; `subagent-return.py` recomputes the same stem at
return and promotes it. Both are registered hooks on both hosts.

**You may not depend on observing the write.** A courier's verdict is written by
`.agent-guild/scripts/codex-courier.py` through Bash, and the kit registers write
hooks only on `Write|Edit|MultiEdit` with no `PostToolUse` anywhere. A mechanism
keyed on seeing the write cannot fire, and an earlier revision of this job's
constitution specified exactly that and was unbuildable.

Requirements, all from the constitution:

- A lane-suffixed verdict discharges only via the gate's own record (C-1).
- The record is made on a Codex read-only return too, where the courier returns
  its outcome and the PARENT persists the file (`subagent-return.py` around
  :451-457). A design that only works when the courier writes the file strands
  every Codex-lane debt forever.
- A stem already present when its courier was dispatched is not recorded, so a
  forged file is not laundered by the next legitimate dispatch (C-1).
- An authorized crossing **does** discharge (C-1). A predicate that discharges
  nothing passes the forge check and is wrong; the check is blind to that
  direction on purpose, and C-8's allow-cases are where it is caught.
- A stem left unauthorized stays clearable by a `…-<lane>.denied` waiver at that
  stem. Note the ordering: `_lib.py:271` (lane-json presence) is tested before
  `:281` (`.denied`), so where you conjoin authorization decides whether the
  waiver is reachable. Pin the outcome, not the ordering.
- A foreign-stem write is refused or surfaced through one of two observable
  channels, naming both Task-IDs: a non-zero hook exit whose stderr names them,
  or a row under `.agent-guild/state/log/` (C-2).
- A verdict written concurrently by a different agent for its own task must not
  block an unrelated return. Concurrency is real here: the incident run overlaps
  `checker-courier T-001` with `worker-standard T-002` (C-2).
- `second_opinion_debts()` keeps its four existing discharge behaviors and stays
  total across the four malformed inputs C-5 enumerates. It never raises;
  `stop-gate.py` calls it every turn.
- **Both lanes.** The conformance script exercises the `codex` lane only, so a
  codex-only implementation passes it while a forged `-claude.json` still
  discharges. Handle both.

On tests (C-8): a test that asserts nothing does not count. Every new gate branch
needs a paired refuse-case and allow-case, differing in exactly one input and
producing opposite outcomes. The checker will verify decisiveness by neutralizing
your branch in a copy of your delivered code and confirming the case flips, so
write cases that actually depend on the gate's decision. Note the checker has two
readings available for "neutralize" (restore the pre-change decision, which flips
the refuse-case; or disable the branch, which flips the allow-case) — write both
kinds of case so either reading finds what it needs.

Do not modify `.agent-guild/state/check-141-conformance.py`; its digest is pinned
in C-3 and editing it fails the clause.


**Commit your own work.** C-9 checks a commit subject, and a working-tree diff
has none. When your artifacts are in place and your own verification passes,
commit them with a conventional-commit subject carrying a type and a scope, and
a body saying why the change was made rather than what it changed. Do not push;
the orchestrator owns that.

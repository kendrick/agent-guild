## Spec excerpt

T-001 makes a lane-suffixed verdict discharge a debt only when the gate recorded
the crossing as authorized. That creates a state the contract does not currently
describe: a stem carrying a verdict nobody authorized, which no future dispatch
will authorize, because a pre-existing stem is never recorded. The debt stays
outstanding, and the escape hatch has to be the `…-<lane>.denied` waiver.

Today the contract still says the waiver is for something narrower in two of the
three places that describe it. A stem poisoned by an unauthorized write is
neither "a host that refused the dispatch outright" nor "a lane that never got as
far as a courier at all".

T-001 already widened the state map entry (`.agent-guild/CLAUDE.md:125`) as part
of landing the mechanism, so that one is done. **Two remain, and all three must
end up saying the same thing:**

- `.agent-guild/CLAUDE.md:87` — the dual-check regime's list of what discharges a
  debt. Still reads "for a host that refused the dispatch outright."
- The inline comment on `second_opinion_debts()`'s waiver branch in
  `.agent-guild/hooks/_lib.py`, which carries its own narrow paraphrase. Find it
  by the `.denied` branch rather than by line number; T-001 moved the code.

Read `:125` first and match it. It is the fullest statement of the rule and the
other two should agree with it, not diverge into a third phrasing.

This is the orchestrator contract: prose that agents read as instructions every

### opus r0

- **C-1** (major): Both widened locations assert that a stem left unauthorized can never be authorized by a later dispatch, and the delivered code contradicts that for the exact case the contract names as its example. CLAUDE.md:87 says "Re-dispatching won't clear it: a stem that already carries a file is never reserved ... So waive it", and _lib.py:484-487 says "reserve_crossing skips a stem that already carries a file (the anti-laundering rule), so no later dispatch can authorize this one". True only when no reservation ever existed (a forged file, or a courier the gate never gated). A courier that died after writing its verdict -- the case CLAUDE.md:125 and C-1 both pick as the illustration -- leaves an unpromoted reservation on disk, reserve_crossing never deletes it, and the NEXT courier's return promotes it (promote_crossing at _lib.py:307-321 keys only on the record's task_id, not on whether this dispatch reserved it), so the debt discharges. Fix by scoping the claim rather than dropping it: say re-dispatch cannot help a stem with no reservation behind it, and that the waiver is the hatch for that case; a stem whose courier died after a legal dispatch is still recoverable by re-dispatching, which is the outcome to prefer because it yields real comparison data for #34 instead of a recorded absence.
  evidence: Replay through the real gates, scratch project, task at complete (script: scratchpad/e2e.py): '1. dispatch-guard #1 rc: 0 / reservation on disk: [T-050-sonnet-r0-codex.authorized]' -> courier writes T-050-sonnet-r0-codex.json then dies -> '2. after courier died mid-flight, stop-gate rc: 2 | debt named: True' -> re-dispatch -> '3. dispatch-guard #2 (re-dispatch) rc: 0' -> '4. subagent-return rc: 0 / authorization record: {"task_id": "T-050", "promoted": true, ...}' -> '5. stop-gate after re-dispatch rc: 0 ... VERDICT: re-dispatch CLEARED the debt'. Direct _lib probe on the same shape: 'E re-dispatch reserve (expect False): False / E re-dispatch promote: True / E authorized after re-dispatch: True / E debts after re-dispatch: []'.

## Spec excerpt

Two things, in this order.

**1. Cut the branch.** Every task in this job commits to one branch. Create it off `main` and stay on it:

```sh
git checkout -b chore/courier-lane-cleanup main
```

Never push it, and never set an upstream tracking ref. The user pushes; you do not.

**2. Add the missing suite to CI.** `.agent-guild/scripts/test_codex_courier.py` is the only test of `codex-courier.py`, which is where issue #106's whole guarantee lives — validate before persisting, retry once on malformed vendor output, emit a `blocked` verdict on the second failure. That test file appears in no workflow in this repo, so every assertion it holds runs locally and nowhere else.

Add it to the suite list in `.github/workflows/plugin-build.yml`. The list is a plain `run:` block of `python3 <path>` lines under a `Run Test Suites` step, indented ten spaces like its neighbours. The `.agent-guild/scripts/` entries in it are in alphabetical order, so the new line belongs directly after `python3 .agent-guild/scripts/test_claude_courier.py`.

The line must be live: indented into the `run:` block, not commented out, and nothing else on it.

**Commit it.** One commit, message explaining why the gap mattered rather than restating the diff — the file under test carries a guarantee that was going unverified in CI. Nothing else changes in this commit.

**Do not** edit `plugin/` or `plugins/agent-guild/` by hand. Those are build outputs. A workflow file is not a build input, so this task needs no `build-plugin.py` run — but if you find `python3 scripts/build-plugin.py --check` already dirty on a clean checkout, stop and report it rather than committing over it.

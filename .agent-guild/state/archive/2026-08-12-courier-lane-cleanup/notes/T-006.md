# T-006 self-report

## What I did

Added `relativize_artifact(path, root)` / `relativize_artifacts(artifacts, root)`
to `.agent-guild/scripts/ledger-append.py` and called it in `main()` right
after `parse_args`, before `build_line`/`schema_violation` run. `root` is
`os.getcwd()`, the same base `DEFAULT_LEDGER` and `SPEC_PATH` already use
(deliberately not `SCRIPT_DIR`, per the spec — this script gets copied into
other projects).

Rules implemented:
- Not `os.path.isabs(path)` → return the value untouched. This is a hard
  early return, not a normalize-and-compare-equal check, so a relative value
  with a formatting quirk (e.g. a leading `./`) can never be touched.
- Absolute and normalizes under `root` (equal to root or starts with
  `root + os.sep`) → `os.path.relpath(normalized, root_norm)`.
- Absolute and outside `root` → the original `path` string is returned as-is
  (not even `os.path.normpath`'d), so it's byte-identical to what was passed
  and never a `../` chain.
- Not existence-gated — no `os.path.exists` call anywhere in the new code,
  unlike `_courier_lib.repo_relative`, which I left untouched (zero diff,
  confirmed with `git diff`).

## Test genuineness (C-5)

Wrote three cases in `test_ledger_append.py`: under-root absolute becomes
relative, `./sub/a.py` (already relative) stays byte-identical, and an
absolute path outside root stays byte-identical with no `../` in it.

I mutation-tested each case myself in throwaway `cp -a` copies before
committing, since C-5's checker will do the same:
- Removing the whole `relativize_artifacts` call → only case 1 fails.
- Removing the `not os.path.isabs(path)` guard (so relative values also run
  through the general normalize/relativize path) → only case 2 fails. This
  is why case 2 uses `./sub/a.py` rather than `sub/a.py`: a plain
  already-under-root relative value round-trips unchanged through the
  general algorithm too, so it wouldn't have caught this specific bug class.
  A leading `./` only survives if relative values are truly skipped rather
  than merely landing on the same output by coincidence.
- Removing the outside-root branch (unconditional `os.path.relpath`, the
  exact bug in C-14's failing example) → only case 3 fails, and it fails
  exactly the way the failing example describes (a `../../../...` chain).

Full suite: 47 passed, 0 failed, both before and after `build-plugin.py`
regenerated the two package copies.

## Judgment calls

- Placed the rewrite call in `main()` rather than inside `build_line()`,
  since the spec offered both as valid ("between those two, or on the
  values before build_line sees them") and `main()` keeps `build_line`
  a pure assembly function with no filesystem-path judgment in it.
- For the outside-root case, I return the original `path` string exactly
  (no `os.path.normpath`), so double slashes or other incidental formatting
  in a user-supplied out-of-root value survive untouched — "written exactly
  as given" read literally.

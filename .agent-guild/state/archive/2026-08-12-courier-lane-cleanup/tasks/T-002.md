**What #106 reported.** A vendor response carried unescaped double quotes inside a JSON string — the observed shape was an `evidence` payload whose own text contained quotes — and the malformed output was truncated rather than caught.

**The harness you replay through.** `.agent-guild/scripts/test_codex_courier.py` builds a fake `codex` executable and puts it on `PATH`, switching behavior on a `FAKE_CODEX_MODE` env var. It already has a `malformed` mode and a `malformed_once` mode, and cases for malformed-once (retry succeeds) and malformed-twice (blocked verdict). Read them before writing anything.

The existing `malformed` fixture emits the literal string `NOT_JSON`. That is not #106's shape: it fails to parse at character one, where an embedded-quote payload parses partway and truncates. **Add a case driving a response whose JSON string value contains unescaped double quotes**, using #106's payload shape, and assert what the harness does with it.

**The four live acceptance criteria the evidence has to demonstrate,** not assert:

1. Nothing reaches the lane-suffixed verdict stem unvalidated.
2. The fixed lane retries exactly once.
3. The second failure produces a schema-conforming `blocked` verdict.
4. The raw attempts are retained under `.agent-guild/state/log/courier-raw/<stem>.jsonl`.

**The fifth criterion changed by design.** #106 also asked that vendor JSON never be "repaired, reformatted, or re-serialized". #142/#144 amended that deliberately: the runner stamps `model` locally from the lane's pinned identity — a model asked to write its own name is guessing — and therefore re-serializes, recording the divergence as an `info` finding and retaining the raw response.

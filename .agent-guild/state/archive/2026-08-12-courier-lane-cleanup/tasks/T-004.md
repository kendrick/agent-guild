## Spec excerpt

This is issue #128 itself: script-checked clauses stop crossing the courier lane. A deterministic clause crosses today as pre-run output for the far side to judge, so it agrees by construction and is worth nothing as second-opinion evidence — `.agent-guild/templates/task.md` has said so in its Courier comparison guidance since before the composer could act on it.

All work is in `.agent-guild/scripts/compose-brief.py` and `.agent-guild/scripts/test_compose_brief.py`.

**The partition.** `extract_clause` returns a clause's verbatim `### C-N: <name>` block — the heading plus every bullet line — as one opaque string. Nothing currently parses the bullets. Add a helper that pulls the `- **check**:` line out of a block and tests its value.

Keep a clause **only** when that value starts with `checker-judgment:`. The prefix is anchored: a clause whose check merely contains the string somewhere — say a script invoked as `check-foo.sh --mode checker-judgment:x` — is a script-checked clause and is dropped.

A dropped clause is dropped **entirely**: not moved to a context section, not summarized, not named. The issue settled that.

**The new exit status.** A task whose cited clauses are all script-checked has nothing to cross. That is not the existing no-clauses-cited error and must not share its exit code:

- exit **3**, with exactly this on stderr: `compose-brief: nothing to cross: <task-id> cites only script-checked clauses`
- **no brief file is written on that path.** A brief sitting at a stem no courier may legally cross is an artifact nothing will ever collect.

Today `compose()` is pure — it returns `(brief_text, None)` or `(None, error_message)` and never sets an exit code — while `main()` returns 1 for both its argument error and every error `compose()` reports, and 0 on success. Thread the new outcome out of `compose()` (a third return element is the natural minimal change) and branch on it in `main()` before the file is written. Exit 3 collides with nothing. Update the module docstring, which currently documents only 0 and 1.

**Three test shapes** in `test_compose_brief.py`, following its existing style — a module-level `check(label, cond, detail)` accumulator, hand-written fixture strings, and a `run()` helper that invokes the real script as a subprocess with `cwd` set to a temp state dir:

1. **mixed** — a task citing one script-checked and one judgment clause: the script clause's id and its check line are both absent from the brief; the judgment clause survives verbatim.
2. **all-judgment** — byte-identical to what today's composer produces.
3. **all-script** — exit 3, the exact stderr string, and no brief written.

**The suite will go red before you have written a single new case, and that is expected.** Its fixture constitution defines its clauses with `- **check**: some check.` and `- **check**: some check two.` — neither judgment-prefixed — and its task fixtures cite those clauses. Under the partition, every existing task fixture in that file becomes an all-script task: exit 3, no brief, and every golden-file assertion fails at once.

The fix is the fixture, not the filter. Give the fixture constitution clauses a `checker-judgment:` prefix on their check lines and update the golden constants to match, remembering that a brief embeds the clause block verbatim including its check line. **Do not loosen the prefix test to make the goldens pass** — that is `"checker-judgment" in check_value` arriving by a different road, and it is the exact defect C-13's failing example names.

Nor do the two requirements collide. C-13's byte-identical comparison is the pre-change composer against the new one **on the same fixture**, recovered with `git show $(git merge-base main HEAD):.agent-guild/scripts/compose-brief.py`. It is not new output against a stale golden constant, so you are free to rewrite those constants.

**Tests must be genuine.** Each case has to go red when the production change it covers is backed out. An all-script case asserting merely "non-zero exit" passes against the old code, which already exits 1 on that input, and so distinguishes nothing.

**What this task does not do.** The `.skipped` marker's hook plumbing is T-003 and is already done — do not touch `_lib.py` or `dispatch-guard.py`. This task cites C-7 across all four of its sites, but three of them are T-003's code and are forbidden to you: if a C-7 operation fails at one of those, say so in your return and stop. That is a defect in delivered work you may not edit, and it is the orchestrator to rule on, not your rework. The role text, contract, and template are T-005.

**Commit.** `.agent-guild/scripts/` is a build input: run `python3 scripts/build-plugin.py` and commit the regenerated packages in the same commit. Never hand-edit `plugin/` or `plugins/agent-guild/`. Run the `humanizer` skill over the commit message; it should say why a deterministic clause is worthless as second-opinion evidence, not just that a filter was added.

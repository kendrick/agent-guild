## Spec excerpt

Issue #47: `.agent-guild/scripts/ledger-append.py` writes whatever `--artifacts` values it is handed, so an absolute path under the repo root lands in the ledger as an absolute path and stops resolving the moment the row is read from anywhere else.

**The change.** Before the assembled line is validated, rewrite each `--artifacts` value that resolves under the repo root to a repo-relative path. The base is `os.getcwd()` — the same base the script already uses for `DEFAULT_LEDGER` and for reading `spec.md`'s provenance `ref`, and deliberately not the script's own location, because this script is copied into other projects where a script-relative path would find this repo while appending to that project's ledger.

Rules:

- A value already relative is unchanged.
- A value resolving **outside** the root is written exactly as given. Never emit a `../` chain — an unconditional `os.path.relpath` turns an artifact under `/var/folders/...` into `../../../var/folders/...`, a path that resolves nowhere but one working directory.
- The rewrite is **not** existence-gated: a path resolving under the root is relativized whether or not a file sits there.

**Ordering matters.** The rewrite runs **before** `schema_violation`, not after. A path the schema has already accepted is a path the ledger has already committed to. Today `build_line()` packs `args.artifacts` straight through and `main()` validates the assembled line before appending; the rewrite belongs between those two, or on the values before `build_line` sees them.

**The courier pre-pass stays.** `.agent-guild/scripts/_courier_lib.py` has a `repo_relative(path, root)` helper that both relativizes **and** drops a path whose file does not exist, returning `None`. `codex-courier.py` maps it over its artifact list before shelling out. Leave it exactly as it is. It looks redundant once the script-level backstop exists and it is not: deleting it silently changes what a courier logs for a missing artifact, since the helper drops such a path and the backstop would keep it. The script-level fix is a backstop for every other caller — a human running `ledger-append.py` by hand, or a future courier that skips the helper.

**Three test cases** in `.agent-guild/scripts/test_ledger_append.py`, in its existing style (a `run()` helper invoking the real script as a subprocess against a `tempfile.TemporaryDirectory`, `check(label, cond, detail)` assertions, and helpers that read the written ledger back):

1. an absolute path under the root → relative in the written row;
2. an already-relative path → unchanged;
3. an absolute path outside the root → untouched, and no `../` anywhere in it.

`--ledger PATH` already exists, so every case can write to a temp ledger.

**No archived ledger is rewritten.** Nothing under `.agent-guild/state/archive/` changes — not to "fix" old absolute paths, not for consistency. Three closed runs live there and every issue in this job forbids touching them.

**Tests must be genuine.** Each case has to go red when the rewrite is backed out.

**What this task does not do.** `--attempts` and `--discarded` are T-007. Do not add them here.

**Commit.** `.agent-guild/scripts/` is a build input: run `python3 scripts/build-plugin.py` and commit the regenerated packages in the same commit. Never hand-edit `plugin/` or `plugins/agent-guild/`. Run the `humanizer` skill over the commit message; it should say why an absolute path in a ledger row is a path that stops resolving, not merely that a rewrite was added.

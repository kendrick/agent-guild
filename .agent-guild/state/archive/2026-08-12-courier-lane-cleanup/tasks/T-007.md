## Spec excerpt

Issue #116 makes a retried crossing visible in the ledger. One row per crossing stays the shape — a retry does not become a second row — but the row says how many attempts it took and what was thrown away. This task is the contract and the appender; the couriers that populate it are T-008.

**1. `.agent-guild/schemas/vendor-call.schema.json`**

Add two properties, both **optional** — neither goes in `required`. Optional is what keeps all 21 archived ledger rows valid; the same pattern the #117 job used.

- `attempts`: `integer`.
- `discarded`: an `array` whose `items` are objects carrying `reason`, `duration_ms`, `exit_code`, `tokens_in`, `tokens_out`.

Types inside a `discarded` entry mirror the top-level fields of the same name exactly: `reason` is `string`, `duration_ms` is `integer`, `exit_code` is `integer`, and `tokens_in` and `tokens_out` are each `["number", "null"]`. That nullability is not decoration — an attempt whose usage the vendor never reported writes `null`, never a fabricated `0`, which is the reason the top-level token fields are spelled that way.

`additionalProperties: false` stays. Keep the keyword set conservative — `type`, `properties`, `required`, `items`, `enum`, `additionalProperties` — because `validate-verdict.py`'s hand-rolled validator pattern covers this schema and does not implement more.

**This is a shared contract.** `.agent-guild/hooks/test_hooks.py` is one of its quieter consumers. Run the full verification block, not just this file's own suite: the #43 job scoped a schema change to the schema's own tests and shipped the hook suite red for the next job to find.

**2. `.agent-guild/scripts/ledger-append.py`**

- `--attempts N`, an integer.
- `--discarded`, repeatable (`action="append"`), each occurrence taking one JSON object per discarded call.

Validate the assembled line exactly as today — the new fields go through `schema_violation` with everything else, before the ledger file is touched. Keep the script's existing posture: it never reads, rewrites, or repairs existing ledger content, and a nullable figure the caller did not supply stays `null` rather than becoming `0`.

Update the module docstring, which documents the flag set.

**3. `.agent-guild/scripts/test_ledger_append.py`**

Cover the new flags and the schema: a row carrying `attempts` and one `discarded` entry validates and reads back intact; a row carrying neither still validates (that is the archived-row guarantee, tested directly rather than assumed); a `discarded` entry whose token figures were not supplied comes back `null` and not `0`. Follow the file's existing style — `run()` against a temp dir, `check(label, cond, detail)`, and helpers that read the ledger back.

**Tests must be genuine.** Each case has to go red when the schema or flag change it covers is backed out.

**No archived ledger is rewritten**, and nothing under `.agent-guild/state/archive/` changes. The whole point of optional fields is that 21 rows written before this change stay valid untouched.

**What this task does not do.** Per-attempt timing and usage capture is T-008 for `codex-courier.py` and T-009 for `claude-courier.py`. Do not touch either courier.

**Commit.** `.agent-guild/scripts/` and `.agent-guild/schemas/` are build inputs: run `python3 scripts/build-plugin.py` and commit the regenerated packages in the same commit. Never hand-edit `plugin/` or `plugins/agent-guild/`. Run the `humanizer` skill over the commit message; it should say why the fields are optional, which is the archived-row compatibility, not merely that two properties were added.

## Spec excerpt

The ledger schema and the `--attempts` / `--discarded` flags landed in T-007. This task makes **the codex courier** populate them. The claude courier is T-009 and you do not touch it.

**The two figures the loop currently destroys.** In `.agent-guild/scripts/codex-courier.py`, the two-attempt loop in `run_courier`:

- **Duration is cumulative.** `duration_ms` is recomputed on each pass but always measured from a single `started_clock` set once before the loop. Time each `_run_once` call individually and keep that figure.
- **Usage is summed on sight.** Each pass reads `_usage(events)` and folds the result straight into `usage_totals`. Capture the per-attempt values before they are merged.

`exit_code` and enough to derive `reason` are already kept per attempt in `raw_attempts`.

**Two artifacts your instruction reaches that you might not expect.** `raw_attempts` is serialized verbatim into `.agent-guild/state/log/courier-raw/<stem>.jsonl`, so anything you hang off it changes the shape of a persisted record. And the outcome this script assembles is published to stdout as the courier's return contract, so a new key added there changes what the parent reads, not just what the ledger stores. Neither is forbidden, but decide both deliberately rather than discovering them — carrying the new figures in a parallel structure keeps both artifacts as they are.

**Fix the suite crash before you mutation-test.** `test_codex_courier.py` dereferences `outcome["persisted"]["raw_path"]` where `outcome` can be `None`, and the suite aborts there partway through — T-002's checker hit it and had to evaluate cases in isolation to work around it. It is two lines, it is in a file this task already has open, and C-5's mutation arm cannot run honestly against an instrument that dies mid-run. Guard the dereference. That guard is exempt from C-5's own mutation requirement: it is a fix to the test harness rather than a behavior under test, and demanding a test that goes red without it would be asking for a test of a crash.

**Do not touch `_courier_lib.ledger_record`.** That helper builds the `ledger` payload for **both** couriers, and the Codex-host parent validates the claude courier's returned payload against an exact key set. Adding a key there brakes that lane. Pass the per-attempt data to `_append_ledger` as its own argument alongside the ledger dict, and let `_append_ledger` turn it into `--attempts` and one repeated `--discarded` per non-final attempt, with `reason` set to that attempt's validation failure. T-009 owns widening the shared helper and the validator together; that seam exists precisely so this task does not have to.

**Two invariants the row must keep.**

- Top-level `tokens_in` and `tokens_out` remain the **cumulative sums** across attempts, so a cost total means what it meant before this change. `test_codex_courier.py` already pins that sum at 108 and 26 for the `malformed_once` case; those numbers should not move.
- `quota_event` is untouched. A quota abandonment stays distinguishable from a retried crossing, and no `discarded` entry is invented for it.

**Never a fabricated zero.** An attempt whose usage the vendor did not report writes `null` for `tokens_in`/`tokens_out`. No fixture in the suite exercises that path, so it is on you to get right by construction rather than by test.

**Tests** in `.agent-guild/scripts/test_codex_courier.py`: a retried crossing's ledger row carries `attempts: 2` and exactly one discarded entry, whose `duration_ms` is that attempt's own elapsed time and **not** the row's own `duration_ms` — assert against that equality specifically, because reusing the cumulative clock is the plausible wrong implementation. A quota abandonment keeps `quota_event` true with no discarded entry. The harness builds a fake vendor executable on `PATH` and switches on env vars; `malformed_once` and the quota modes already exist, so reuse them.

**Tests must be genuine.** Each case has to go red when the capture change it covers is backed out.

**Nothing under `.agent-guild/state/archive/` changes.**

**Commit.** The harness guard and the per-attempt capture are two unrelated changes, so they are two commits — C-10 judges granularity and a commit mixing them is a finding. `.agent-guild/scripts/` is a build input: run `python3 scripts/build-plugin.py` and commit the regenerated packages in the same commit as the source change that caused them. Never hand-edit `plugin/` or `plugins/agent-guild/`. Run the `humanizer` skill over the commit message; it should say why a retry that costs nothing measurable is a hole in a cost ledger.

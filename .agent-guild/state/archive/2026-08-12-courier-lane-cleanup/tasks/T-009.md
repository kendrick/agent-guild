## Spec excerpt

T-008 gave the codex courier per-attempt capture. This task mirrors it in `.agent-guild/scripts/claude-courier.py` and — the part that makes it possible — widens the parent contract that would otherwise refuse the result.

**Read this first, because it inverts the obvious approach.** `claude-courier.py` never invokes `ledger-append.py`. It has no `LEDGER_PATH`, and its only subprocess call is the vendor CLI itself. A Codex project agent cannot write its own ledger, verdict, or exhaustion sentinel, so the courier returns an outcome payload and the parent persists it.

That parent validates the payload by **exact key set, twice**, in `.agent-guild/hooks/subagent-return.py`:

- `set(outcome)` must equal exactly `status`, `verdict`, `ledger`, `attempts`, `diagnostic`.
- `set(ledger)` must equal exactly the ten keys `_courier_lib.ledger_record` returns.

So every route to "put the per-attempt figures in the returned payload" trips one of the two comparisons, and the failure is silent in the worst way: the hook blocks the return, the crossing is never promoted, `second_opinion_debts` never discharges, and the debt rides all the way to `STALLED.md`. The Codex-host courier lane stops working in the field while every test stays green — both consumer fixtures hand-build their payloads instead of calling the courier, so nothing in the suite notices.

**What to change.**

1. **`.agent-guild/scripts/_courier_lib.py`** — widen `ledger_record` to carry the `discarded` key described in item 3, optionally. This helper is shared with `codex-courier.py`, which T-008 deliberately left alone for exactly this reason, so this is the one place the shape changes for both lanes.

2. **`.agent-guild/hooks/subagent-return.py`** — widen the `ledger` key-set comparison to accept `discarded` as **optional**, so a payload with it and a payload without it both pass. Leave the `set(outcome)` comparison where it is; nothing here needs a new top-level outcome key. Keep the comparison strict about unknown keys — the point is to admit that one, not to stop checking.

   **Items 1 and 2 land in the same commit.** Split across two, the branch carries a commit where the helper emits a key the validator refuses — the exact defect this task exists to prevent, sitting in history instead of at the tip, and C-2 walks every commit.

3. **`.agent-guild/scripts/claude-courier.py`** — capture per-attempt duration and usage in the two-attempt loop, measuring per `_run_once` rather than from the shared clock and taking usage before the running sum.

   **The shape is pinned here, not inferred from the codex lane.** T-008 deliberately keeps the codex figures out of `ledger` and routes them straight to `_append_ledger`, so there is no sibling implementation to copy. Add exactly one key, `discarded`: an array of objects carrying the five members C-4 names — `reason`, `duration_ms`, `exit_code`, `tokens_in`, `tokens_out` — with the types C-4 pins. Do **not** add `attempts`. That is already a top-level key of the outcome and the parent validator pins it to `1` or `2`; a second `attempts` inside `ledger` would be a duplicate of a field the contract already carries.

4. **`.agent-guild/hooks/test_codex_adapter.py`** — its `courier_outcome` fixture hand-builds the payload, which is why the gap was invisible. Add a case that asserts the accepted key set matches what `claude-courier.py` actually emits, so the next widening of the payload cannot drift past the gate the way this one would have.

5. **`.agent-guild/scripts/test_claude_courier.py`** — the returned `ledger` payload carries the per-attempt figures on a retried crossing, and a quota abandonment stays distinguishable: `quota_event` unchanged with no `discarded` entry invented for it. The spec asks both courier suites for that second case; T-008 covers the codex side and this is the claude one.

**This is not the excluded work.** The job's non-goals rule out threading `--discarded` flags through the Codex-host parent that calls `ledger-append.py` on the courier's behalf. That is a different concern from the parent's validator refusing the payload at the door, and the second one has to be fixed or the deliverable cannot exist. Do not go hunting for the code that assembles the eventual `ledger-append.py` call; do fix the validator that gates the return.

**6. Finish the harness guard T-008 started**

T-008 guarded `outcome["persisted"]` in `test_codex_courier.py`, which is the dereference its task file named. Its checker then found an earlier one that still kills the run: around line 393, `outcome['identity']` is dereferenced unguarded, so under any mutation leaving `outcome` as `None` the suite aborts ten lines before the guarded site and the fix has no observable effect yet. Two checkers on this job have already lost time to that abort.

Guard it the same way. This is instrument repair, not behavior, so it is **exempt from C-5's mutation arm** on the same reasoning T-008 carried: a test that went red without it would be a test of a crash. Keep it in its own commit, separate from the courier work, since C-10 judges granularity.

**Tests must be genuine.** Each new case has to go red when the change it covers is backed out — including the validator case, which should fail against the unwidened key set.

**Nothing under `.agent-guild/state/archive/` changes.**

**Commit.** `.agent-guild/scripts/` and `.agent-guild/hooks/` are build inputs: run `python3 scripts/build-plugin.py` and commit the regenerated packages in the same commit. Never hand-edit `plugin/` or `plugins/agent-guild/`. Run the `humanizer` skill over the commit message; it should say why a payload the courier can build and the parent will not accept is worse than a red test.

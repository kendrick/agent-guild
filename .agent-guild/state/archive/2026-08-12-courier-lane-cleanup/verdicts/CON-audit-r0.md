## Diagnosis

- **C-3** (blocker) and **C-9** (major): the two path guards fail open, silently.
  Both are built on `git diff --name-only main...HEAD`, which is empty in two states a worker reaches by accident and one they reach by mistake. Demonstrated on a local clone at `/private/tmp/claude-501/-Users-k-arnett-repos-agent-guild/7188fa38-b39f-46d7-9b46-9e5e2fe93992/scratchpad/probe`:
  - Work committed on `main` with no job branch: C-3 exit 0, C-9 exit 0, with a modified archived ledger and an out-of-scope `docs/` file in the commit.
  - Work uncommitted on the job branch: C-3 exit 0, C-9 exit 0, same two violations sitting in `git status`.
  The second state is the common one. A checker dispatched the moment a worker returns sees an uncommitted tree, and both guards report clean. Neither check errors on the missing precondition; they pass. Fix by making the precondition part of the check — fail unless `git rev-parse --abbrev-ref HEAD` is `chore/courier-lane-cleanup`, and diff against `main` including the worktree (`git diff --name-only main` plus `git status --porcelain`, or `git diff --name-only $(git merge-base main HEAD)` with `--` and an added untracked-file sweep) rather than `main...HEAD` alone.

- **C-5** (blocker): the mutation procedure is not executable by checker-judgment as written.
  constitution.md:43 instructs the checker to "revert the corresponding production edit in the working tree". `guild-core/roles/checker-judgment.md` closes with "Do not edit artifacts or fix problems yourself; you have no Edit tool by design." The agent does carry Bash and Write (`.claude/agents/checker-judgment.md:5`), so the instruction is possible but forbidden — a checker following its role returns `blocked` every round, and one following the clause mutates the artifact it was sent to judge. It also leaves three steps for the checker to invent: where the mutation happens, how restoration is verified, and how "each test the task added or changed" is enumerated (nothing points at a diff, and on an uncommitted tree there is no diff to point at). Fix by pinning the venue and the enumeration: mutate in a throwaway `git clone --local` or `git worktree` under the scratch directory, never the job branch; enumerate the new cases from the task's artifact list; report the clone path, the mutation applied, and the observed failure text per case. Say in the clause text that the mutation is a check instrument in a disposable copy, not a repair, so the clause and the role stop contradicting each other. Also note the incentive C-5 creates on its own: it can only bite tests that exist, so a worker who writes fewer tests faces a smaller C-5 — which is why the coverage gaps below cannot be answered with "C-5 will catch it".

- **C-7** (blocker): a reading rubric on the mechanism the job turns on.
  "Read all four sites and confirm each behaves as stated" (constitution.md:55) is satisfiable by restating the diff. Three of the four sites have a cheap executable form, and the clause should require it: run `compose-brief.py` against an all-script fixture and compare stderr byte-for-byte with the string the clause already specifies in full; construct a stem carrying `T-NNN-<tier>-r0-<lane>.skipped` and observe `second_opinion_debts` return no debt for it; file the same marker under the far host's lane and observe the debt stand.

- **C-2** (major): the check tests the tip, the text claims every commit.
  constitution.md:24 encodes the intake decision that packages are regenerated with the change that caused them, "so `--check` is clean at every commit rather than only at the branch tip". `python3 scripts/build-plugin.py --check` reads the current worktree once. Source in commit 1 and packages in commit 3 violates the text and passes the check. Fix by iterating: `for c in $(git rev-list main..HEAD); do git stash …; git checkout $c …` is heavy — cheaper is a per-commit check on the task's own commits, or reduce the text to what the check verifies and put the per-commit rule where it can be seen, in C-10's commit review.

- **C-4** (major): an untested requirement, resting on an ambiguous convention.
  The text (constitution.md:36) requires "the numerics inside `discarded` follow the nullable convention the existing token fields use"; the check (:37) never looks. Archived rows carry no `discarded` key, so the archived-row half of the check cannot reach it either. Worse, `discarded` (spec.md:62) is `{reason, duration_ms, exit_code, tokens_in, tokens_out}` and the live schema treats those names two different ways: `tokens_in`/`tokens_out`/`cost_usd` are `["number","null"]`, while top-level `duration_ms` and `exit_code` are bare `integer`. A worker has two defensible readings and the checker has no rubric to choose between them. Fix by writing the intended types into the clause text field by field, and adding the read to the check.

- **C-10** (major): the clause requires a process no artifact can evidence.
  "Has been through the `humanizer` skill's audit-and-revise loop rather than written from a memory of its principles" (constitution.md:72) is unfalsifiable: clean prose written without the skill is indistinguishable from clean prose written with it, and there is no failing example I can construct for the process claim alone. The check silently swaps in an output standard, which is the right standard — so state that standard in the text and drop the process claim, or give the process an artifact (the worker records the invocation in its notes and the clause cites it). Separately, move branch name, upstream-ref absence, and commit granularity into a deterministic check; those three facts need no judgment, and the branch-name check is the missing precondition C-3 and C-9 need.

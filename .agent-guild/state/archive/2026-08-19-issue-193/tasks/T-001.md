## Spec excerpt

Three independently motivated changes to `.agent-guild/scripts/check-job-spec.py`. All three land in this one file; the suite cases for them belong to T-002, and regenerating the published trees belongs to T-003.

**1. Relax R10's adjacency requirement.** `_governs_plural_noun` reads the text immediately after the number and requires a word ending in `s`, so `Four rules constrain how:` fires but `Four further rules constrain how:` does not — any adjective between the count and its noun disables the rule. This is not hypothetical phrasing: the `kendrick/dotfiles#22` decomposition carried `Three further rules constrain how:` above three bullets. That count happened to be correct, and nothing would have said so if it were not.

Relax it so the plural noun may be separated from the count by one or more modifiers, while keeping the rule from firing on a number that governs no list. The relaxation may live in `_governs_plural_noun` or in its caller `find_r10_violation` — both are legitimate factorings and C-9 accounts for each. Do NOT key on a fixed list of adjectives or on a suffix pattern: C-1 exercises modifiers invented at run time, so any allowlist or morphology gate fails it.

**2. Add R21, a checker-routing rule.** The routing table in `.agent-guild/CLAUDE.md` assigns a checker by clause kind — a clause checked by a script routes to `checker-deterministic`, a clause checked by a rubric routes to `checker-judgment` — and nothing enforces it. Fail a task whose `checker` is `checker-deterministic` while any clause it cites has a `checker-judgment:` check method, naming the task and the offending clause and no other clause the task cites.

Only that direction is harmful and only that direction gets a rule: a `checker-deterministic` handed a rubric cannot apply it, because that agent runs scripts and exercises no judgment. The reverse — a `checker-judgment` carrying script clauses — is safe, has house precedent in the archive, and must keep exiting 0.

Four constraints on the implementation:

- **Read the clause kind from the constitution, not from the task's `check_method` paraphrase of it.** A task's own prose can disagree with the clause it names, and a rule reading the paraphrase reports the wrong clause on any task citing several — 36 of the archive's 40 tasks cite more than one.
- **R21 is the rule number**, because R20 is taken by #139's lint-exception guard. Add an explicit `PROOF` entry to `RULE_CLASS` rather than relying on the unrecognized-rule fallback: `rule_R20` consults that mapping to decide whether a `**Lint exception**` may waive a rule.
- **Skip it under `--audit-id CON-audit`,** the way every other task-reading rule does — see the rule-ordering commentary at `check-job-spec.py:22-42`. A CON round is audited before tasks exist, so a routing rule has nothing to read there; and a CON round dispatched *after* Phase 1 would otherwise judge a populated `tasks/` against a phase that never asked about it.
- **Place it ahead of every heuristic in `run_rules`.** `RULE_CLASS` marks R2, R9, R10 and R12 as heuristics and `run_rules` reaches R2 first, so R21 goes before R2. Paperwork carrying both a routing defect and an inferred one must report the unwaivable proof rather than the waivable guess.

**3. Name the anchor in R2's diagnostic.** `nearest_anchor` picks the backticked span closest to the citation within its sentence, and a markdown list introduced by a colon keeps that sentence open across every bullet and into the fields below — so the anchor can come from several lines away. The message today reports the citing location and two target line numbers, but never the anchor text nor the line the anchor itself sits on, leaving an author to permute prose until the rule goes quiet. That cost `dotfiles#22` two rounds.

Quote the anchor text the rule matched and state where that anchor sits in the citing document. Both positions must read correctly: an anchor on a line of its own, and an anchor sharing the citation's line. Quoting style is yours — backticks, `!r`, or none at all.

**Build that message in a function named `r2_anchor_message`, taking the matched text as a parameter named `anchor`.** This is a seam the constitution requires so a later check can remove the anchor while leaving R2's older cases standing; C-9 explains why, and a differently-named parameter fails it.

**Do not change R2's anchor-selection algorithm.** The #132 heuristic and its sentence scoping stay exactly as they are — only the diagnostic changes. R2 must also stay silent exactly where it is silent today: a quoted span absent from the whole cited file is evidence the span was never that citation's anchor, not evidence the citation is wrong.

**Stdlib only.** Hooks run this file as a bare `python3` call with no venv, so a third-party import becomes `HOOK ERROR` and exit 2 for every dispatch in every project running the kit.

**Do not touch `.agent-guild/scripts/test_check_job_spec.py` or any generated tree.** Both belong to other tasks, and editing a generated tree by hand is never correct here.

**Do not commit anything.** C-7 checks this job's diff scope by reading the *uncommitted* working tree — `check-diff-scope.py` unions `git status --porcelain` with `git diff --name-only`, both of which go blank once work is committed. A commit here would leave that check reporting `OK: 0 path(s) in scope` and passing without inspecting anything, so an unrelated edit could ride along unnoticed.

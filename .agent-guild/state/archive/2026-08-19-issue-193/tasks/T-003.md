## Spec excerpt

Regenerate this repo's published trees from the sources T-001 and T-002 changed, then confirm every consumer of `check-job-spec.py` is still green.

`.agent-guild/scripts/check-job-spec.py` and its suite are build inputs: `scripts/build-plugin.py` copies them into `plugin/` and `plugins/agent-guild/`. Those trees are **generated views and must never be hand-edited** — run the builder and let it write them.

Steps, in order:

1. Run `python3 scripts/build-plugin.py` bare, which rewrites the published trees from source.
2. Run `python3 scripts/build-plugin.py --check`, which must exit 0 — it fails if any published file differs from a fresh build.
3. Confirm all four consumer commands exit 0: `python3 .agent-guild/scripts/test_check_job_spec.py`, `python3 .agent-guild/scripts/check-job-spec.py --self-test`, `python3 .agent-guild/hooks/test_hooks.py`, and `python3 scripts/build-plugin.py --check`.

`test_hooks.py` is on that list because `dispatch-guard` runs `check-job-spec.py` as a gate and parses its exit code, so a change to the linter has consumers beyond its own suite.

You own the generated trees and nothing else. **Do not edit `.agent-guild/scripts/check-job-spec.py` or `.agent-guild/scripts/test_check_job_spec.py`.** If a consumer suite fails, report it rather than fixing it here — the fix belongs to whichever task owns that file.

**Do not commit anything.** This matters more here than anywhere else in the job: your checker is the one that runs C-7, the job's only diff-scope check, and it reads the *uncommitted* working tree. `check-diff-scope.py` unions `git status --porcelain` with `git diff --name-only`, and both go blank once work is committed — so a commit at this point leaves C-7 reporting `OK: 0 path(s) in scope` and passing without inspecting a single file. Nothing detects that. No hook or script in this repo runs `git commit` on your behalf, so the only way it happens is if you do it.

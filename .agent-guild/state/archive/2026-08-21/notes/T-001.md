# T-001 self-report

## What I did

Rewrote the payload sync engine in `scripts/plugin-src/install-project.py` to be
provenance-driven, then regenerated `plugin/` and `plugins/` via
`python3 scripts/build-plugin.py`.

Key changes:
- Added `_package_version(host)`: reads the running package's own manifest
  (`.claude-plugin/plugin.json` or `.codex-plugin/plugin.json`, both siblings
  of `project-template/`) at run time via `PACKAGE_ROOT`, so a copied package
  with a rewritten manifest stamps its own version rather than a compiled-in
  string.
- Added `_load_provenance(path)`: returns the prior `files` map, or `{}` for
  both a brand-new project and a pre-provenance one.
- Replaced `_copy_missing` + the old preflight-conflict logic with
  `_sync_payload(...)`, which decides per file:
  - missing on disk -> copy from source, record its hash (net-new).
  - on disk, recorded hash present and matches on-disk bytes -> clean
    against its record, so upgrade to current source and restamp
    (regardless of whether the stamp trails the plugin's).
  - on disk, recorded hash present and differs -> real local edit; preserve
    bytes, carry the recorded hash forward untouched, report the path.
  - on disk, no recorded entry (pre-provenance) -> adopt at on-disk hash if
    it matches source; otherwise preserve and record no entry (so a later
    revert to shipped bytes gets adopted on its own, and a later re-init
    doesn't retroactively trust it).
- `_preflight_payload` now only runs the `_require_beneath` symlink guard
  over every payload path (before any write anywhere in `install()`); the
  conflict-vs-clean decision moved into `_sync_payload`, which still repeats
  the guard defensively per file, matching `_copy_owned`'s existing style.
- `install()` now reads `current_version` up front (fails fast on a
  malformed manifest, before any write), loads `recorded_files` right after
  `target_payload` is defined, and always writes
  `.agent-guild/provenance.json` (`{"version", "files"}`, sorted-key JSON)
  via `_atomic_write` after the state `.gitkeep` files land.

No change was needed for C-6 (the record staying trackable): the existing
`.gitignore` writer only ever appends `.agent-guild/state/`, which doesn't
match `.agent-guild/provenance.json`, so the record is untracked-by-default
correctly once it exists.

## Judgment calls / things worth flagging

- I unified "fresh install", "pre-provenance adoption", and "normal
  upgrade/refuse" into one per-file branch in `_sync_payload` rather than
  three separate code paths, since the constitution's rules turn out to
  reduce to the same decision tree once you key off "does the file exist on
  disk" and "is there a recorded hash for it". This felt like the more
  faithful reading of C-1 through C-4 as one coherent policy rather than
  three separate behaviors, and it's what let all the probes and the
  existing `test_build_plugin.py` cases pass without special-casing.

- Fresh Claude install: record has exactly `version` and `files`, 38 entries, `git check-ignore` exits 1 for `provenance.json` and 0 for `state/`. The verify line I added behaves as documented.

## Unsure about

- **Scope of edit 1.** Fixing that pre-existing sentence was not literally in the spec excerpt. I judged that leaving a contradiction in the same section would fail C-7's "documents ... each behavior a user meets" more surely than a one-clause edit oversteps.
- **The verify-snippet line.** `git check-ignore -q PATH; test $? -eq 1 && echo ...` is uglier than the `&& echo` form its neighbors use. I chose it on purpose: `|| echo` would print "provenance record tracked" on exit 128 too, which is a false positive outside a git repo. If a checker prefers the parallel form, that is a taste call I can go either way on.
- **"a sha256 for each payload file".** Strictly, a pre-provenance file that differs gets no entry at all, so the record does not always cover every payload file. The adoption section states that exception explicitly, and I chose the simple general statement plus the stated exception over hedging the first sentence.
- I did not document the session nudge, which reads the record's stamp. C-7 names four behaviors and the nudge is not among them, so I left it alone rather than expand scope.
